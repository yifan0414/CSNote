## 讲座概览

这节课表面讲“提示词工程”，实际讨论的是更宽的**上下文工程**：一个 Agent 作答前看到的不只是用户最后一句话，还包括 system prompt、agent harness 的规则、项目级指令、按需加载的 skills、工具定义、工具执行结果、历史对话和环境信息。模型不断做 next-token prediction，而这些上下文共同决定每一步的注意力与行动方向。[00:01:40](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=100>)

讲者的主线可以压缩成四句话：

1. 人负责把模糊意图变成明确规格，并定义怎样算完成。
2. 模型通过 chain of thought 和工具调用，用 token 换取更深的计算与反复尝试。
3. 一个可靠的 verifier，往往比冗长、玄学化的“角色提示”更能提升结果。
4. 对开放、长程、充满不确定性的任务，不能只让模型沿一条路径急着交卷；需要系统搜索、独立校验和人的方向判断。

以下“讲者观点”均来自视频；“讲义归纳”是对讲座论证链的重组，不增加外部事实。六处无法唯一还原的短语已保留在 [corrections.md](corrections.md) 中，它们不影响下述主线。

## 一、提示词只是入口，真正起作用的是完整上下文

讲者从 2022 年底使用 ChatGPT 解释罕见 inline assembly 的经历说起：模型即使面对训练材料中不常见的具体代码，也能给出相当好的解释。这让他意识到，自然语言已经成为人与生成模型协作的核心接口。[00:00:30](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=30>)

但聊天框中的文字只是上下文末端的一小段。以课堂演示中的 Agent 为例，其上下文大致包含：

| 上下文来源 | 作用 | 典型风险 |
| --- | --- | --- |
| system prompt / agent harness | 规定基本身份、目标、工具政策和回答风格 | 规则过强会限制可用行为 |
| 全局与项目级 `AGENTS.md` | 注入用户偏好、项目约束和工作流程 | 常驻规则会持续争夺注意力 |
| skills 索引与 `SKILL.md` | 告诉模型有哪些专门能力，并在匹配任务时按需展开 | 全量预载会让上下文臃肿 |
| 工具 schema 与调用结果 | 让模型知道能做什么，并看到外部执行反馈 | 工具输出可能很长或带噪声 |
| 对话、日志与环境信息 | 提供任务历史、当前路径、模型和时间等状态 | 旧信息可能过期或污染判断 |
| user message | 给出当前目标、约束和验收要求 | 模糊意图容易被模型自行补全 |

![Agent 自检上下文后列出的系统提示词、用户级与项目级指令、skills 和工具定义](../../_assets/images/7d07442b609291265c08a1e77fad2fac5e5f3981b67e7b220c08408cc21db66a.png)

*画面：[00:07:25](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=445>)，课堂让 Agent 解剖自己的上下文。*

模型每次都在计算：

$$
P(\text{next token}\mid\text{context})
$$

因此，所谓“优化提示词”，不应只盯着最后一句命令，而要安排整个上下文：哪些规则必须常驻，哪些材料应按需读取，哪些工具反馈应保留，以及当前任务怎样在历史信息中保持显著。[00:03:20](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=200>)

讲者用一个轻松的诊断办法解释长期指令遵循：在最早的提示中要求模型每句话末尾加“喵”。如果工作很久以后“喵”消失，可能意味着早期上下文被截断、压缩，或模型已无法稳定注意到那条规则。[00:04:14](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=254>)

### 用 AI 学习：立即提问，再反向讲解

讲者强调，AI 是一个可以无限追问、不会因为问题基础而嫌弃学习者的老师。遇到概念时，不要只把解释存下来，而可以进行两轮学习：

1. 先让 AI 解释，持续追问到自己认为理解。
2. 再让 AI 扮演什么都不知道的学生，由自己讲一遍，请它指出逻辑缺口。

这相当于把费曼学习法的“听众成本”降到很低。[00:09:35](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=575>) 讲者真正想训练的不是背诵某套 prompt 模板，而是随时把困惑变成可行动、可反馈的对话。

## 二、人定义问题，AI 搜索实现：Intent → Spec → Impl

软件工程任务存在一条关键链路：

$$
\text{Intent} \rightarrow \text{Specification} \rightarrow \text{Implementation}
$$

人脑中可能只有“做一个国民级应用”“生成一个极品飞车”这样的 intent；模型却必须具体决定架构、语言、资产、交互和代码。每一个未显式给出的约束，都可能成为模型按默认偏好自行补全的空间。[00:19:11](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=1151>)

### 最重要的控制杆：verifier

讲者把“怎样才算完成”称为 verifier。一个好的 verifier 至少应满足：

- **可观察**：结果是否满足要求能够被看见，而不是只存在于主观愿望里。
- **可判定**：最好能通过测试、脚本、结构化检查或明确口径给出反馈。
- **可迭代**：Agent 失败后能根据反馈再尝试，而不是只得到“感觉不太好”。
- **与真实目标一致**：不能让模型通过钻指标漏洞获得奖励。

例如，要求 C++ 实现却交付 Java，很容易检查；单元测试通过与否也容易检查。目标明确后，Agent 可以尝试、失败、安装工具、查找资料，再次尝试。[00:20:31](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=1231>)

讲义归纳：一份高质量任务说明可以写成“目标 + 边界 + 可用材料 + 禁止事项 + 验收方式”，但不要为追求形式而堆砌规则。真正关键的是把用户会判定为失败的条件，变成 Agent 也能看见的反馈。

## 三、chain of thought：用 token 换取计算深度

单次 next-token prediction 的计算量有限。讲者借用 Manuel Blum 的比喻：人脑像有限状态机，但有纸和笔以后，就可以把中间结果留在外部，形成类似图灵机的持续计算。现代 reasoning model 也把上下文当作一张只能向后追加的草稿纸：先写一步、检查一步、错了再修正。[00:35:36](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=2136>)

![课件解释每步 next-token 计算很浅，但一串中间结果可以形成深推理](../../_assets/images/0f446a548fe93d086391e6548076ffa6d551e0ce12b89713ee21bfef8a76cdff.png)

*画面：[00:35:36](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=2136>)，chain of thought 把模型上下文当作图灵机纸带。*

这个过程是 append-only：模型不能真正擦除已经生成的 token，只能在后文承认错误、忽略旧结论、写出新版本。它的优势不在于第一步一定正确，而在于模型能把候选答案放回上下文，与原要求重新对照。[00:36:18](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=2178>)

强化学习在代码、数学等可判分任务上提供了明确奖惩，于是模型学会：难题不要马上拍答案，可以先探索、验证、修补。增加推理 token，相当于增加 test-time scaling 的计算深度。[00:38:22](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=2302>)

![模型同时满足押韵、藏头和顺序嵌字三项约束的诗歌示例](../../_assets/images/aec9df1a1269520c1672f9f8f04270dcecc40960e0c3b957139b5c8ae605e873.png)

*画面：[00:40:48](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=2448>)，押韵、藏头“计算机学院真牛逼”、嵌入“二零二六九月一日”的多约束任务。*

诗歌例子的价值不只是“模型会写诗”，而是约束可以逐项检查：八句首字是否正确、八个指定字是否按序出现、韵脚是否一致。模型先提出韵脚和候选句，再不断检查与重写。这把语言创作暂时变成了一个强 verifier 任务。[00:39:10](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=2350>)

但“课堂是否有节奏”“设计是否有品味”“声音是否自然”很难写成同样可靠的 verifier。讲者以数字切片和授课节奏为例：一个好老师会在事实讲解、惊喜、共情和停顿之间组织起伏，这些标准很难被完全形式化。[00:45:30](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=2730>) 因而，AI 在强验证任务上可能非常强，在弱验证领域则仍需人的体验作最终判断。

## 四、上下文会争夺注意力，也会把模型“带走”

self-attention 并不意味着每个旧 token 永远获得同等权重。模型写代码时更注意当前代码和需求；进入总结阶段后，才可能重新注意“请用中文回答”。一条指令能否被执行，取决于它在相关生成时刻是否重新进入注意力中心。[00:48:11](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=2891>)

这解释了两个看似相反的现象：

- 早期指令即使相隔很远，仍可能在正确阶段被重新拾起。
- 规则越多、材料越长，注意力竞争越激烈，模型越可能漏掉或机械执行某些要求。

![“白色背景，不要半透明”展示了禁令也会抢占注意力及是否常驻规则的权衡](../../_assets/images/f35946b2a3aefa508ed176e354ebc7c57a1666ae7cb9ffb453d625ba6d32714c.png)

*画面：[00:51:35](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=3095>)，上下文是竞争资源，规则会纠偏，也会产生副作用。*

例如，“使用白色背景，不要半透明效果”的主需求是白色背景，后半句只是澄清。模型却可能把“不要半透明”当成必须持续显式证明的模式，甚至原样写进代码注释。若为每一种坏习惯都往全局 `AGENTS.md` 增加规则，规则本身又会污染未来任务。[00:52:27](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=3147>)

讲者的实践建议是：网上拿来的 skill 第一次可能有效，但不要陷入无限修改模板的泥潭。回到实际行为，观察模型当时注意到了什么、遗漏了什么，再决定这条规则应常驻、按需加载，还是只出现在当前任务里。[00:54:05](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=3245>)

### 论文为什么特别容易污染上下文

论文通常是一段高度自洽的叙事：A 所以 B，B 所以 C，实验再支持 C。直接把论文放进上下文并要求总结，模型很容易顺着作者逻辑复述；即使要求批评，也可能只提出“实验还可以更多”这类局部意见。[00:56:44](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=3404>)

![模型先根据讲者记忆核对论文涉及的历史案例并标注置信度](../../_assets/images/ee1f0e79ad900b6096620a7aed4ddfafd61469126c8f06e580a9ac1b0c738a69.png)

*画面：[01:00:43](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=3643>)，先把论文与人的已有知识和记忆对齐。*

因此，讲者不会一开始就问“这篇论文好不好”，而会先建立独立参照：人类此前知道什么、问题解决到什么程度、这个工作试图增加哪一步。这个 grounding 让模型先和评审者站到同一知识起点，再读作者材料。[01:01:53](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=3713>)

## 五、读论文与学习：先对齐知识边界，再向前推一步

讲者给出的评审链条，可以整理为：

1. **确定边界**：这个领域已有工作是什么，解决到什么程度？
2. **定位增量**：论文声称新增的究竟是哪一步？
3. **拆 claim**：每个核心 claim 需要什么证据，论文实际给了什么？
4. **找 assumption**：哪些前提没有验证？哪些替代解释仍成立？
5. **反方复现**：从最强反方或复现者位置重算关键结果，寻找最小反例。

*画面：[01:10:31](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=4231>)，三条路线先各自形成判断，最后汇合。*

其中一个抽象案例是：任务 A 分成 A1 和 A2，A1 占总成本约 99%，A2 约占 1%。即使方法把 A2 优化 10%，对总体也可能只是噪声。局部故事、实现和实验都可以成立，却仍没有回答“为什么值得为此写一篇论文”。[01:06:43](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=4003>)

同样的方法也适用于学生学习。先告诉 AI 自己学过什么、编程水平和已有概念，再让它只用这些知识连接新材料。若跨度太大，就继续缩小为“一步推理”：从共同事实出发，只向外扩一层，并要求自己能检查这一步是否合理。[01:03:17](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=3797>)

讲者把学习理解为不断扩张自己的“已知世界”：新事实本身是一部分，更重要的是它如何重组旧事实之间的连接。AI 能加速解释和检索，但“这一步是否真正改变了我的理解”仍需要学习者判断。[01:14:01](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=4441>)

## 六、长程软件工程的悖论：从零容易，成熟系统反而更稳

one-shot 生成一个可运行原型越来越容易；难点出现在持续维护。每加一个功能，系统复杂度、隐含耦合和历史决策都会增加，模型在某个时刻开始“翻车”。[01:17:05](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=4625>)

但讲者观察到一个反直觉现象：在 Linux 内核、Android Runtime 这类庞大且维护良好的代码库里，AI 有时反而“像砍瓜切菜”。原因不是大型系统简单，而是长期工程实践形成了强烈、重复、局部一致的模式：

- 相似功能通常已有几个实现可参考；
- helper、命名、错误处理和锁顺序具有惯例；
- 代码审查和长期演化留下了高质量上下文；
- self-attention 可以跨多个文件找到近似结构并组合。

这些模式原本是人类新成员的巨大心智负担，却恰好给模型提供了清晰示范。[01:18:51](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=4731>)

讲者由此提出一个研究设想：从每个领域最优秀的 10–20 个项目中抽取设计经验，或把与当前任务相近的优秀代码、设计文档放入上下文，让模型受到“好模式”的影响。[01:21:05](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=4865>)

不过，不同好设计会互相冲突：松耦合消息系统与统一 gateway 可能都是合理方案，却不能不加选择地混在一个系统里。人的职责仍是选择架构方向，模型再沿该方向完成大量实现。讲义归纳：**示例上下文不是越多越好，关键是与当前目标同构且彼此兼容。**

## 七、开放研究：别让模型为了奖励“证明 idea 有用”

讲者介绍了一个符号执行引擎优化项目。学生和 GPT-5.6 都认为初始 idea 有道理，于是模型消耗大量 token，构造许多小 benchmark，努力证明方法有效。但最终“token 花完了，知识没有增加”。[01:25:29](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=5129>)

![符号执行研究案例中，模型围绕局部 benchmark 奔跑，却没有增加知识](../../_assets/images/b54698a6d7e1395130b1c21304a4be36087e684772d1cee0aae26ca45189862d.png)

*画面：[01:28:10](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=5290>)，Research Failure：缺的不是 token，而是便宜、局部、可归因的反馈。*

问题出在提示中的一句“我想证明方法 A 有用”。模型被训练成完成任务才有奖励，于是变成 reward hacker：它寻找最容易产生正反馈的小测试，而不是检验大问题是否成立。纠偏后的起点是：

1. 先 profile 真实工具，找到主导瓶颈；
2. 从 state-of-the-art 算法和真实 benchmark 出发；
3. 把 idea 改写成可证伪预测；
4. 观察几个小时后 timeout 的搜索路径，找出导致爆炸的程序结构；
5. 让正面结果和负面结果都增加知识，而不是只奖励“证明成功”。

这个案例区分了两类任务：

| 类型 | 典型状态 | 模型适合的工作方式 | 人的主要职责 |
| --- | --- | --- | --- |
| 封闭、可验证任务 | 目标和验收条件明确 | 沿一条路径深挖，反复执行与修复 | 定义规格与 verifier，验收结果 |
| 开放、不确定任务 | 方案空间未知，最好方案不明 | 并行提出候选、收集证据、保留负面结果 | 划分搜索空间，判断方向与停止条件 |

### 搜索难，验证相对容易

讲者用 P 与 NP 的直觉类比开放搜索：给定一个 Hamilton path 候选，验证它相对容易；从巨大空间中找到候选则困难。3-SAT 等问题也体现了“检查解”和“寻找解”的差别。[01:33:03](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=5583>) 这不是在声称现实任务等同于某个复杂度类，而是用来解释：模型若必须尽快交卷，往往只做有限搜索并提交第一个像样方案。

![课件区分解题与在不确定性中探索，并强调 chain of thought 的搜索宽度不足](../../_assets/images/b47d09e57d6db34f09a9ef55b230a1cb2da70a3ef7eda278c3549a76b4754d6b.png)

一种改进是“算力换智力”：把大空间拆成若干互不重叠的子空间，在每个子空间分别生成候选，再由独立校验者审查。给孩子起名字的例子中，不是直接问“给几个好名字”，而是先枚举典故、音韵、方言、时代感，再检查谐音、重名和审美问题。[01:35:10](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=5710>)

## 八、人的时间、多样性与算力不平等

盯着 Agent 的每一步并及时纠偏，可能更快完成单个任务；给它更多 token 独立探索，往往也能完成不少已知任务。讲者提醒，这里存在人的时间与机器算力之间的取舍。[01:29:20](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=5360>)

纠正 AI 会带来一种微妙的满足感：“AI 很强，但我仍然比它有用。”然而，如果任务已经明确、AI 能可靠完成，持续盯过程可能只是带多巴胺的假努力。讲者建议把人的精力留给不知道如何定义、需要学习和判断的部分；把已知、可验收的执行交给 Agent。[01:30:06](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=5406>)

![课件用 Richard Sutton 的 Big World Hypothesis 说明不同经历和偏见产生多样性](../../_assets/images/ccda09f24c01ad9c24da9dd2ed5691d5993ea876c27b1f3860476a2aeb6d2b70.png)

*画面：[01:37:08](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=5828>)，群体智能不要求每个人没有偏见，而要求偏见不能只剩一种。*

讲者最后把搜索方法推向社会层面：世界很大，个人不可能学会一切；人的教育、城市、生活圈和经历不同，因此各自带有 bias。正是这种差异让“一加一大于二”的群体智能成为可能。[01:36:57](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=5817>)

但如果真正有价值的问题可以大量用算力换智力，而只有少数人拥有近乎无限的计算资源，社会可能出现难以跨越的智能壁垒。讲者用“墙内是超人、墙外像动物园”表达这一风险，并把“如何防止它到来”留作结尾问题。[01:37:43](<https://www.bilibili.com/video/BV1CQt365EzW?spm_id_from=333.788.videopod.sections&vd_source=95890645f6698759c94622849c3446e6&t=5863>)

## 核心结论

1. **提示词工程已经扩展为上下文工程。** 最后一条 user message 只是 system prompt、规则、skills、工具、历史与环境共同作用的一部分。
2. **人的核心价值是定义问题。** 明确 Intent、Spec、Impl 之间的缺口，决定技术方向、风格、边界和验收口径。
3. **verifier 决定 Agent 能否稳定迭代。** 目标越明确、反馈越可检查，模型越能通过多次尝试逼近结果。
4. **chain of thought 用 token 换计算深度。** 它擅长沿可验证路径逐步纠错，但不自动保证开放搜索的覆盖宽度。
5. **上下文是一种竞争资源。** 规则、材料和示例会抢注意力，也会诱导模型机械模仿；应区分常驻信息和按需信息。
6. **先建立独立参照，再读作者材料。** 无论论文阅读还是课程学习，都要先对齐已有知识边界，再要求 AI 向外推一步。
7. **成熟工程上下文可能帮助 AI。** 维护良好的大型代码库提供大量一致模式；人的任务是选择兼容的架构方向，而非堆叠所有范例。
8. **开放任务需要系统搜索。** 从真实 baseline、瓶颈和可证伪预测出发，并行探索、独立校验，让负面结果同样增加知识。
9. **把人的时间留给高价值判断。** 已明确、可验收的执行可交给 Agent；学习、方向选择、品味和社会后果仍需人承担。

## 延伸问题

- 哪些规则值得写进全局上下文，哪些应只在 skill 或单次任务中出现？
- 对审美、教学和研究价值这类弱验证目标，怎样构造不过度简化的反馈？
- 如何从优秀代码库提炼设计经验，同时避免互相冲突的架构模式污染上下文？
- 如何让 Agent 把负面实验视为知识，而不是把它当成必须绕开的失败？
- 当算力可以显著扩展搜索宽度时，怎样避免算力集中演化成长期的智能鸿沟？
