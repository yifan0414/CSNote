## 🤖 Agent

DIG 的“预先算好”分两层：

第一层是 `rewards/*.json`，作者已经离线算好了。  
第二层是你运行 `scripts/video_refinement.sh` 后生成的 `keyframes/*.json`，这是最终 eval 用的帧索引。

流程是这样：

**1. Query Identification**
用一个 LLM 判断每个问题是 `global` 还是 `local`。

代码在 [pipeline/query_identification.py](/ssd_2t/yifan/DIG/pipeline/query_identification.py:31)。

它会把问题送到本地 OpenAI-compatible server，例如 README 里用：

```bash
export MODEL_NAME=Qwen/Qwen3-Next-80B-A3B-Instruct
bash scripts/launch_llm.sh
bash scripts/query_identification.sh videomme
```

输出写到：

```text
data/videomme_meta.json
```

每条样本会多一个：

```json
"query_type": "global" 或 "local"
```

**2. CAFS: 先找候选代表帧**
只对 `local` 问题处理。  
代码在 [pipeline/cafs.py](/ssd_2t/yifan/DIG/pipeline/cafs.py:30)。

它用 `facebook/dinov2-base` 提取视频帧特征：

```python
processor = AutoImageProcessor.from_pretrained("facebook/dinov2-base")
model = Dinov2Model.from_pretrained("facebook/dinov2-base")
```

大致逻辑：

- 按 `sample_per_sec=2` 采样视频。
- 每 60 秒切一段。
- 用 DINOv2 提特征。
- 计算相邻帧特征差异：`1 - cosine_similarity`。
- 用 `find_peaks(..., prominence=0.1)` 找内容变化点。
- 在相邻变化点之间取中点，作为代表帧 `r_frame_idx`。
- 同时保存边界 `boundaries`。

运行：

```bash
bash scripts/cafs.sh videomme
```

**3. Reward Assignment**
对每个 `local` 问题，把第 2 步选出的 `r_frame_idx` 候选帧送给目标 VLM，让它给每帧打 relevance reward。

代码在 [pipeline/reward_assignment.py](/ssd_2t/yifan/DIG/pipeline/reward_assignment.py:40)。

每个候选帧会作为 base64 image 发给 VLM，同时附上问题、视频时长、时间戳。VLM 返回：

```json
{"description": "...", "reward": 75}
```

运行方式类似：

```bash
export MODEL_NAME=Qwen/Qwen2.5-VL-7B-Instruct
bash scripts/launch_mllm.sh
bash scripts/reward_assignment.sh videomme
```

输出就是：

```text
rewards/Qwen2.5-VL-7B-Instruct_videomme.json
```

所以 `rewards/` 是跟目标模型绑定的。Qwen2.5-VL-7B、32B、Qwen3-VL-8B 各有自己的 reward 文件。

**4. Video Refinement**
最后才把 reward 转成真正 eval 用的 keyframe indices。

代码在 [pipeline/video_refinement.py](/ssd_2t/yifan/DIG/pipeline/video_refinement.py:28)。

逻辑是：

- `global` 问题：直接均匀采样 `k` 帧。
- `local` 问题：根据 reward 找高分区域。
- 在高分 r-frame 附近扩一个窗口。
- 合并区间。
- 从这些区间里均匀取 `k` 个最终帧索引。

运行：

```bash
export MODEL_NAME=Qwen/Qwen2.5-VL-7B-Instruct
bash scripts/video_refinement.sh videomme
```

会生成：

```text
keyframes/Qwen2.5-VL-7B-Instruct_videomme_8.json
keyframes/Qwen2.5-VL-7B-Instruct_videomme_16.json
keyframes/Qwen2.5-VL-7B-Instruct_videomme_32.json
...
```

eval 时 DIG 模式读取的就是这些 `keyframes/*.json`：

```bash
bash scripts/eval/qwen25vl.sh videomme DIG
```

简单说：作者已经帮你跑完了 `query identification + CAFS + reward assignment`，所以你现在只需要用 `rewards/` 生成 `keyframes/`，然后 eval。

DINOv2 只在 CAFS 这一步用，位置是：

[pipeline/cafs.py](/ssd_2t/yifan/DIG/pipeline/cafs.py:125)

```python
processor = AutoImageProcessor.from_pretrained("facebook/dinov2-base")
model = Dinov2Model.from_pretrained("facebook/dinov2-base").to(device).eval()
```

它的作用是在 [get_r_frames](/ssd_2t/yifan/DIG/pipeline/cafs.py:30) 里给采样视频帧提视觉特征：

```python
chunk_features_list.append(
    extract_batch_features(model, processor, batch_pil, device).mean(dim=1)
)
```

然后用相邻帧特征差异找内容变化点：

```python
diffs = 1 - F.cosine_similarity(chunk_features[:-1], chunk_features[1:], dim=1)
peaks, _ = find_peaks(diffs.detach().cpu().numpy(), prominence=0.1)
```

最后在变化点之间取中点，得到代表帧 `r_frame_idx`。

运行入口是：

[scripts/cafs.sh](/ssd_2t/yifan/DIG/scripts/cafs.sh:6)

```bash
accelerate launch --num_processes 96 pipeline/cafs.py \
    --dataset "$1" \
    --json_file "data/${1}_meta.json" \
    --video_dir "$vdir" \
    --output_file "data/${1}_meta.json" \
    --sample_per_sec 2
```

所以 DINOv2 不参与最终 Qwen 推理，也不参与 `video_refinement.sh`。它只用于离线预处理阶段，从视频里找 local query 的候选代表帧。

## 👤 User

什么意思,仓库提供了预计算好的什么,有什么用

## 🤖 Agent

仓库提供的“预计算好”的东西就是这些文件：

```text
DIG/rewards/
├── Qwen2.5-VL-7B-Instruct_videomme.json
├── Qwen2.5-VL-32B-Instruct_videomme.json
├── Qwen3-VL-8B-Instruct_videomme.json
├── ...
```

它们的作用：省掉你自己跑 DINOv2 和 VLM 打分的离线预处理。

每条数据里大概长这样：

```json
{
  "video_path": "data/videomme/data/uF3zNOthLAg.mp4",
  "videoid": "uF3zNOthLAg",
  "question": "Which location serves as the battleground in the fight?...",
  "query_type": "local",
  "r_frame_idx": [198],
  "boundaries": [0, 413],
  "reward": [75.0]
}
```

含义是：

- `query_type`：这个问题是全局问题还是局部问题。
- `r_frame_idx`：DINOv2 预先找出来的候选代表帧。
- `boundaries`：视频内容变化边界。
- `reward`：目标 VLM 给这些候选帧打的相关性分数。
- `video_path` / `question`：后续匹配用。

这些文件还不是最终推理用的帧。它们是中间结果。

你运行：

```bash
bash scripts/video_refinement.sh videomme
```

会把 `rewards/*.json` 转成最终 keyframes：

```text
keyframes/Qwen2.5-VL-7B-Instruct_videomme_8.json
keyframes/Qwen2.5-VL-7B-Instruct_videomme_16.json
keyframes/Qwen2.5-VL-7B-Instruct_videomme_32.json
...
```

这些 `keyframes/*.json` 才是 eval 时真正用的文件。里面记录的是：每个视频、每个问题，最终应该抽哪几个帧给 Qwen 看。

所以完整关系是：

```text
DINOv2 + VLM 打分
        ↓
rewards/*.json   仓库已经给了
        ↓  video_refinement.sh
keyframes/*.json  你本地生成
        ↓  eval/qwen25vl.sh DIG
Qwen 按这些帧做评测
```

因此你现在不装 DINOv2也能跑 DIG，因为 DINOv2 的结果已经被保存在 `rewards/*.json` 里了。

是的。只要是仓库 `rewards/` 里没有预计算结果的新数据集，你就需要重新跑完整 DIG 预处理，其中会用到 DINOv2。

对新数据集，流程是：

```text
原始 QA 数据 + 视频
  ↓
query_identification.py
  生成 query_type: global/local
  ↓
cafs.py
  用 DINOv2 找 local query 的候选代表帧 r_frame_idx
  ↓
reward_assignment.py
  用目标 VLM 给候选帧打 reward
  ↓
video_refinement.py
  生成最终 keyframes
  ↓
lmms-eval DIG 推理
```

DINOv2 只在这一步需要：

```bash
bash scripts/cafs.sh <dataset>
```

如果你只跑仓库支持且已有 reward 的这三个：

```text
mlvu
longvideobench
videomme
```

并且目标模型是仓库已有 reward 的：

```text
Qwen2.5-VL-7B-Instruct
Qwen2.5-VL-32B-Instruct
Qwen3-VL-8B-Instruct
```

那就不需要 DINOv2，直接用 `rewards/*.json` 生成 `keyframes/*.json` 即可。

但如果是“其他数据集”，或者同一个数据集但换成没有 reward 的模型，例如别的 Qwen、InternVL、LLaVA，那就需要重新跑 reward pipeline。DINOv2 负责候选帧，目标 VLM 负责给候选帧打分。
