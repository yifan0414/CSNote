# 视频理解论文各阶段使用模型对比

> 目标：不是比较分数，而是回答一个更工程化的问题：**每篇 video understanding 论文在 pipeline 的不同阶段分别用了什么模型？**
>
> 读表时要区分三类“模型”：
> - **Scorer / Retriever**：CLIP、BLIP-ITM、DINOv2、SigLIP、PerceptionEncoder 等，通常负责便宜打分或特征抽取。
> - **Selector / Router / Compressor**：DPP、bandit、router、Mamba projector、KV memory、learned selector 等，决定保留哪些帧、片段或 token。
> - **Answer / Reasoner MLLM**：Qwen、LLaVA、InternVL、GPT、Gemini、o3 等，最终负责回答或复杂推理。

## 0. 统一阶段定义

| 阶段                         | 作用                                                     | 常见模型 / 模块                                                              |
| -------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------- |
| A. Query / option 解析       | 判断问题类型、生成候选答案、抽取实体/关系、规划工具                             | GPT-4o、GPT-3.5、Qwen-VL、Gemini、text-only LLM、o3                         |
| B. 候选帧 / 片段生成              | 1FPS、uniform sampling、scene / shot boundary、clip split | uniform sampler、shot detector、histogram difference、DINOv2 边界信号         |
| C. Relevance / evidence 打分 | 计算 query-frame、query-clip、option-video 相似度             | CLIP、EVA-CLIP、BLIP / BLIP-2 ITM、SigLIP、PerceptionEncoder、Sentence-BERT |
| D. 选帧 / 选片段                | 从候选中选 top-K frames / clips，并保证 coverage / diversity    | DPP、MMR、bandit、GMM threshold、DWT、K-Means、LLM/VLM judge、YOLO-World      |
| E. Token / resolution 压缩   | 决定每帧内保留多少视觉 token 或分辨率                                 | token pruning、token merging、pooling、KV pruning、Mamba projector、router  |
| F. 外部语义 / memory           | caption tree、RAG database、agent tools、visual memory    | BLIP-2、LaViLa、GPT-4.1 captioner、embedding model、FlexMem KV bank        |
| G. 最终推理 / 答案               | 用压缩后的视觉证据回答问题                                          | Qwen2/2.5/3-VL、LLaVA-Video / OV、InternVL、GPT-4o、Gemini、OpenAI o3       |

## 5. 横向观察：哪些模型在什么阶段最常出现？

### 5.1 DINOv2：更适合“保结构 / 找视觉变化”

典型论文：[[Paper/raw/ktv-keyframes-and-key-tokens-selection-for-efficient-training-free-video-llms/KTV Keyframes and Key Tokens Selection for Efficient Training-Free Video LLMs.md\|KTV]]、[[Paper/raw/divide-then-ground-adapting-frame-selection-to-query-types-for-long-form-video/Divide, then Ground Adapting Frame Selection to Query Types for Long-Form Video Understanding.md\|DIG]]、[[Paper/raw/longvu-spatiotemporal-adaptive-compression-for-long-video-language-understanding/longvu-spatiotemporal-adaptive-compression-for-long-video-language-understanding.md\|LongVU]]。

- 优点：捕捉 frame-level visual difference、scene change、coverage。
- 风险：不直接理解 query 或 options，所以通常放在 **query-agnostic temporal coverage** 阶段。

### 5.2 CLIP / SigLIP / BLIP-ITM：更适合“便宜打分”

| 模型 | 常见用途 | 代表论文 |
| --- | --- | --- |
| CLIP / CLIP-like | query-frame similarity、frame diversity、attribute / event focusing | Q-Frame、D-CoDe、KTV、Nar-KFC、SURGE* |
| EVA-CLIP-L | 粗筛 query-relevant candidates | A.I.R. |
| BLIP ITM / BLIP-2 ITM | pairwise image-text matching score，更像 relevance scorer | AKS、FOCUS、WFS-SB、Q-Gate |
| SigLIP | stronger dual encoder / data labeling / selector features | K-frames、LongVU、M-LLM selector、Evidential Sampling |
| PerceptionEncoder PE-G/14 | video-text retrieval over segments | VQOS |

经验上：

- **CLIP / SigLIP** 快，适合大量帧 embedding cache 与粗筛。
- **BLIP-ITM / BLIP-2 ITM** 慢一些，但 pairwise matching 更像“这帧是否能回答 query”的 scalar score。
- **PerceptionEncoder** 更适合 segment-level video-text retrieval，而不是单帧静态图文相似度。

### 5.3 GPT / Qwen / InternVL / LLaVA：既可当 judge，也可当最终 answerer

同一个大模型在不同论文里角色不同：

| 角色 | 使用方式 | 代表论文 |
| --- | --- | --- |
| Query classifier / gater | 判断 query type、expert weights | DIG、Q-Gate、HiMu |
| VLM analysis / reward | 对少量候选帧细判 relevance | A.I.R.、DIG |
| Captioner / database builder | 给 clip / frame 生成 captions 或 subject registry | DVD、VideoTree、HiCrew |
| Decomposer / refiner | 分解问题、生成 sub-QA、选择 refined answer | D-CoDe、C2R |
| Final answerer | 读取最终 frames / tokens / memories 输出答案 | 几乎所有 VideoQA 方法 |

关键区分：

> **用 MLLM 给所有帧逐帧打分太贵；更常见策略是：CLIP/BLIP/PE 粗筛，大模型只对少量候选做 judge 或最终推理。**

### 5.4 内部 attention / KV cache：白盒方法的核心资产

代表：[[Paper/raw/prunevid-visual-token-pruning-for-efficient-video-large-language-models/prunevid-visual-token-pruning-for-efficient-video-large-language-models.md\|PruneVid]]、[[Paper/raw/dycoke-dynamic-compression-of-tokens-for-fast-video-large-language-models/dycoke-dynamic-compression-of-tokens-for-fast-video-large-language-models.md\|DyCoke]]、[[Paper/raw/scaling-the-long-video-understanding-of-multimodal-large-language-models-via-vis/scaling-the-long-video-understanding-of-multimodal-large-language-models-via-vis.md\|FlexMem]]、[[Paper/raw/one-token-per-highly-selective-frame-towards-extreme-compression-for-long-video/one-token-per-highly-selective-frame-towards-extreme-compression-for-long-video.md\|XComp]]、[[Paper/raw/videorouter-query-adaptive-dual-routing-for-efficient-long-video-understanding/videorouter-query-adaptive-dual-routing-for-efficient-long-video-understanding.md\|VideoRouter]]。

- 优点：更贴近最终语言模型真正关注的 visual tokens / memories。
- 缺点：需要访问 hidden states、attention、KV cache 或修改 forward graph；对闭源 API 不友好。

## 6. 按“是否训练 / 是否白盒”快速归类

| 类型 | 代表论文 | 特点 |
| --- | --- | --- |
| Training-free black-box / plug-and-play | AKS、Q-Frame、WFS-SB、A.I.R.、FOCUS、CoSeLECT、mDP3、DIG、VQOS、Q-Gate、HiMu、VideoTree、DVD、C2R | 易接现有模型；主要成本在额外 scorer / LLM call |

| Full model / benchmark / task line | Video-ChatGPT、ROS-DVC、Video-MME-v2 | 更像基础模型、任务或评测协议，而不是单纯前处理模块 |

## 7. 对后续方法设计的启发

1. **如果目标是低成本复现 baseline**：优先实现 CLIP/BLIP-based frame scorer + MMR/DPP/segment allocation，例如 Q-Frame、WFS-SB、mDP3。
2. **如果目标是长视频 sparse evidence retrieval**：VQOS、A.I.R.、DIG、HiMu、Q-Gate 更值得对比，因为它们显式利用 query / option / modality routing。
3. **如果目标是 token budget 极限压缩**：KTV、DyTo、FLoC、SURGE、PruneVid、XComp 是核心对比对象。
4. **如果目标是复杂推理 / EgoSchema 类任务**：D-CoDe、C2R、HiCrew、DVD 的 reasoning / agent 部分比单纯选帧更关键。
5. **如果目标是闭源 API 可用**：避免依赖 KV cache / hidden states 的方法，优先用外部 scorer + selected frames + prompt 的 pipeline。

## 8. 一句话总结

> 视频理解论文中，**DINOv2 常用于保持视觉结构，CLIP / BLIP / SigLIP / PE 常用于打分与检索，YOLO / OCR / ASR / CLAP 常用于专家证据，Qwen / LLaVA / InternVL / GPT / Gemini 常用于 judge 与最终推理，attention / KV cache 则是白盒 token compression 的核心信号。**
