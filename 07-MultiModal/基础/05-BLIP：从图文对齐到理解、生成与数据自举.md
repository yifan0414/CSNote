> **BLIP 用同一套部分共享参数的模型，分别学习“图文是否语义接近”“这对图文是否真正匹配”“看图后下一个词是什么”；再把学到的生成与匹配能力用于补写、过滤训练文本，用改进后的数据预训练新模型。**

理解 BLIP，可以沿着四个问题展开：

| 核心问题 | 简要答案 |
| --- | --- |
| 监督信号从哪里来？ | 图文配对关系，以及配对文本自身的 token 序列；同时使用人工标注数据与网络图文数据 |
| 网络如何表示图文？ | ViT 图像编码器 + MED 文本侧，在独立编码、图文融合编码、图像条件解码之间切换 |
| Loss 如何构造？ | ITC 做跨样本对比，ITM 做图文配对二分类，LM 做图像条件下的 next-token prediction |
| 哪些参数与数据会更新？ | 在线模型联合训练，动量分支通过 EMA 更新；CapFilt 在另一阶段生成、筛选文本，构造新训练集 |

下文依次解释：**配对监督 → 三种运行模式 → ITC 对齐 → ITM 匹配 → LM 生成 → 梯度与参数更新 → CapFilt 数据自举 → 下游使用 → 完整心智模型**。

前置阅读：[[01-CLIP：从图文配对到共享语义空间]]。

本文讨论的是原始 **BLIP**，不是 BLIP-2。论文全名为 *Bootstrapping Language-Image Pre-training for Unified Vision-Language Understanding and Generation*。下文的小例子与展开公式用于解释机制；涉及动量分支、参数共享和损失实现的细节，结合原论文与官方代码核对。

## 1. 监督信号：同一对图文，可以构造三种学习任务

### 1.1 从 CLIP 的问题继续往前走

假设数据中有一对 $(I_1,T_1)$：

- 图片 $I_1$：一只狗在草地上跑。
- 文本 $T_1$：“a dog running on grass”。

CLIP 主要问：

> 给定这张图片，在一批文本里，哪段文字是它的配对文本？

BLIP 保留这种**全局对齐**，但还增加两个问题：

> 把图片与某段文字放在一起仔细看，它们是否真正匹配？
>
> 不给完整描述，只给图片和已经写出的前缀，接下来应该写什么？

前一个问题**要求模型学习跨模态交互**；后一个问题**要求模型拥有生成文本的能力**。仅仅得到两个相似的向量，并不会自动得到能逐词生成句子的解码器。

### 1.2 三个目标的标签分别是什么？

对于包含 $B$ 对图文的 batch：

$$
\mathcal{B}=\{(I_i,T_i)\}_{i=1}^{B},
\qquad
T_i=(t_{i,1},t_{i,2},\dots,t_{i,L_i}).
$$

可以从同一批数据构造：

| 训练目标 | 给模型什么？ | 要预测什么？ | 标签从哪里来？ |
| --- | --- | --- | --- |
| ITC：Image-Text Contrastive | 图片或文本，以及另一模态的候选集合 | 正确配对对象在候选集合中的位置 | 数据中的配对关系；原始 BLIP 还混入动量模型的软目标 |
| ITM：Image-Text Matching | 一对完整的图片和文本 | matched / unmatched | 原始配对作为正例，采样得到的错配作为负例 |
| LM：Language Modeling | 图片与文本前缀 | 下一个 token | 配对文本中紧随前缀的真实 token |

例如，把 $I_1$ 与另一张图片的文本 “a dog sleeping on a sofa” 配在一起，可以构造一个 ITM 负例；把 “a dog running on grass” 右移一位，就能构造 LM 的输入与目标。

因此，**不需要分别为三个目标人工标注三套标签**。不过，这也不意味着完全没有人工监督：原始 BLIP 的训练数据包含 COCO、Visual Genome 等人工标注图文数据，CapFilt 也会在 COCO 上微调。

### 1.3 天然配对，不等于文本一定正确

网络图片的 alt-text 可能是：

- 与画面相关的描述：“a dog running on grass”。
- 只与网页背景相关的文字：“my weekend diary”。
- 广告、文件名、模板文字，甚至错误描述。

即使数据告诉模型 $I_i\leftrightarrow T_i$，也不能保证 $T_i$ 精确描述了 $I_i$。同样，错配的 $T_j$ 也可能在语义上适用于 $I_i$，形成 false negative。

BLIP 从两个层面处理这个问题：

- **训练目标层面**：ITC 使用动量模型产生软标签，缓和“所有非配对文本都绝对错误”的假设。
- **数据层面**：CapFilt 为图片生成新描述，并过滤原始描述和生成描述中的噪声。

这两个机制相关，但不是同一件事。参见 [BLIP 论文第 3 节](https://arxiv.org/abs/2201.12086)。

## 2. 网络架构：一个视觉编码器，三种文本侧运行模式

### 2.1 MED 不是三个完全独立的模型

BLIP 的核心架构叫 **MED：Multimodal Mixture of Encoder-Decoder**。

它可以运行成：

1. **Unimodal encoder**：图像和文本分别编码，用于 ITC。
2. **Image-grounded text encoder**：文本通过 cross-attention 读取图像，用于 ITM。
3. **Image-grounded text decoder**：文本通过 causal self-attention 和 cross-attention 逐步生成，用于 LM。

![[_assets/images/BLIP-2201.12086-01-med-architecture.png|900]]

上图来自原论文 Figure 2；相同颜色表示共享参数。理解时重点看：**是否启用 cross-attention，以及文本 self-attention 是双向还是因果的。**

| 模式 | 文本 self-attention | 文本是否读取图像 token？ | 主要输出 |
| --- | --- | --- | --- |
| 独立编码 | 双向 | 否 | 图像、文本各自的全局向量 |
| 图文融合编码 | 双向 | 是，通过 cross-attention | 依赖当前图文配对的融合表示 |
| 图像条件解码 | 因果 | 是，通过 cross-attention | 每个位置对下一个 token 的预测分布 |

这里的 mixture 指组合不同编码、解码功能，**不是带路由器的 MoE 专家混合架构**。

### 2.2 图像侧：既保留全局表示，也保留 token 序列

ViT 将图片编码成：

$$
H_i^I=f_{\theta_{\mathrm{vision}}}(I_i)
\in\mathbb{R}^{P\times d_v},
$$

其中 $P$ 表示包含 CLS 在内的视觉 token 总数，$d_v$ 为视觉 hidden size。

它有两种用途：

- **ITC**：取 CLS 表示 $h_{i,\mathrm{CLS}}^I$，投影成全局图像向量。
- **ITM / LM**：把整个 $H_i^I$ 作为 cross-attention 的视觉输入，不只是提供一个 CLS 向量。

因此，BLIP 并不是把所有任务都压缩成“比较两个全局 embedding”。需要检查细节或生成描述时，文本侧能够读取视觉 token 序列。

### 2.3 独立编码：先各自理解，再比较向量

ITC 分支的文本编码与 BERT 类似：

$$
T_j
\xrightarrow{\text{双向 Text Encoder}}
H_j^T\in\mathbb{R}^{L_j\times d_t}
\rightarrow h_{j,\mathrm{CLS}}^T.
$$

这一分支关闭 cross-attention。因此，编码 $T_j$ 时不需要指定它对应哪张图片，编码 $I_i$ 时也不需要指定候选文本。

这正是独立编码适合大规模检索的原因：**候选库里的图片或文本向量可以提前计算，再用向量相似度快速搜索。**

注意与原始 CLIP 的文本侧区分：BLIP 在这里取文本 CLS 表示，而不是 CLIP 的 EOT 表示；BLIP 的这一文本编码模式使用双向注意力。

### 2.4 融合编码：cross-attention 到底融合了什么？

在图文融合模式中，每个文本 Transformer block 的主体可简化为：

$$
\text{双向 Self-Attention}
\rightarrow\text{Cross-Attention}
\rightarrow\text{FFN}.
$$

省略多头拼接、残差和 LayerNorm，单个 cross-attention head 可以写成：

$$
Q_T=H^T W_Q,
\qquad
K_I=H^I W_K,
\qquad
V_I=H^I W_V,
$$

$$
\operatorname{CA}(H^T,H^I)
=\operatorname{softmax}
\left(\frac{Q_TK_I^\top}{\sqrt{d_k}}\right)V_I.
$$

其中 $H^T$ 是当前层文本 self-attention 后的状态，$H^I$ 是视觉编码器输出。若文本长度为 $L$，注意力权重矩阵属于 $\mathbb{R}^{L\times P}$，每个文本位置都可以对视觉 token 分配权重。

- **Query 来自文本**：当前词及其上下文需要什么视觉信息？
- **Key / Value 来自图像**：视觉序列提供哪些可供读取的内容？

例如，要区分 “running on grass” 与 “sleeping on a sofa”，模型可以结合动词、地点和图片细节，而不仅仅确认“图里有狗、句子里也有 dog”。这是架构提供的交互能力，不保证注意力图天然就是准确的目标定位图。

在序列起始处使用任务 token `[Encode]`，其输出表示：

$$
h_{ij}^{\mathrm{fuse}}
=\operatorname{MED}_{\mathrm{enc}}(T_j,H_i^I)_{\mathrm{Encode}}
\in\mathbb{R}^{d_t}.
$$

这个表示同时依赖 $I_i$ 和 $T_j$：**同一句话换一张图片，融合表示也可能变化。** 它不能像独立文本 embedding 那样，对所有图片只预计算一次。

### 2.5 条件解码：不是只把 encoder 换一个名字

LM 分支将文本侧换成 causal self-attention：

$$
\text{Causal Self-Attention}
\rightarrow\text{Cross-Attention}
\rightarrow\text{FFN}.
$$

生成第 $t$ 个 token 时，只能使用此前的文本 token，但可以读取整张图片的视觉特征：

$$
p_\Theta(t_t\mid t_{<t},I).
$$

因果限制针对**文本序列**，并不是要求图像 patch 也按顺序逐个开放。

论文用 `[Decode]` 表示序列起始 token。官方 tokenizer 对应的实际字符串为 `[DEC]`，融合编码的任务 token 为 `[ENC]`；图中的 `[Encode]` / `[Decode]` 是功能记法。参见 [官方 tokenizer 定义](https://github.com/salesforce/BLIP/blob/main/models/blip.py#L186-L191)。

### 2.6 参数如何共享？

MED 的预训练设计是：**文本 encoder 与 decoder 共享除 self-attention 层之外的参数**，包括公共的 embedding、cross-attention 和 FFN 等部分；任务输出头承担各自职责。

- ITC 与 ITM 使用文本 encoder 的双向 self-attention，ITC 不执行 cross-attention。
- LM 使用独立参数的 causal self-attention。
- ITM 与 LM 共享 cross-attention；文本模式之间共享公共的 embedding 和 FFN。

所以，不应把 BLIP 理解成“同一个 self-attention 只换一个 mask，所有权重完全不变”，也不应理解成“三套互不相关的完整网络”。论文的共享策略位于两者之间。参见 [BLIP 论文第 3.1–3.2 节](https://arxiv.org/abs/2201.12086)与[官方参数绑定实现](https://github.com/salesforce/BLIP/blob/main/models/blip_pretrain.py)。

## 3. ITC：先把图文放进可以比较的共享空间

> [!abstract] 先抓住主线，再记名词
> **BLIP 的 ITC 仍然是双塔独立编码、比较全局向量、在候选集合中做 softmax 分类，没有增加 cross-attention。** 相比你熟悉的 CLIP，它主要扩展了两件事：**候选从哪里来，以及分类目标怎么定。**
>
> - **候选这条线**：想增加候选，但不想只靠增大 batch → 缓存历史特征（队列）→ 希望缓存特征的来源变化更平缓 → 使用慢更新副本（动量编码器）。
> - **标签这条线**：非配对文本也可能描述同一内容 → 不把所有非配对对象都一概视为绝对错误 → 混合真实配对标签与动量模型的判断（软目标）。
>
> 这是帮助理解设计的因果链，不是要求先单独训练队列、再训练动量模型。下面逐步拆开。

### 3.1 从 CLIP 出发：先各自编码，再在候选中找配对

假设当前 batch 有 $B=3$ 对图文。拿“狗在草地上跑”的图片作为查询对象，比较当前的三段文本，目标是找出它的配对描述。

两侧取全局 CLS 表示，通过可学习投影映射到同一维度：

$$
z_i^I=W_I h_{i,\mathrm{CLS}}^I+b_I,
\qquad
z_j^T=W_T h_{j,\mathrm{CLS}}^T+b_T,
\qquad
z_i^I,z_j^T\in\mathbb{R}^{d}.
$$

再进行 $L_2$ 归一化，把向量长度变为 $1$：

$$
\bar z_i^I=\frac{z_i^I}{\lVert z_i^I\rVert_2},
\qquad
\bar z_j^T=\frac{z_j^T}{\lVert z_j^T\rVert_2}.
$$

**暂时忽略动量分支和队列**，熟悉的相似度 logit 就是：

$$
s_{ij}=\frac{(\bar z_i^I)^\top\bar z_j^T}{\tau},
\qquad \tau>0.
$$

| 计算步骤 | 通俗理解 |
| --- | --- |
| 投影 | 把图像、文本表示映射到可以比较的同维空间 |
| 归一化后点积 | 比较两个向量的方向，即余弦相似度 |
| 除以温度 $\tau$ | 调节候选分数经过 softmax 后有多尖锐 |
| Softmax + 交叉熵 | 希望分配给正确配对的概率更高 |

只考虑当前 batch 和硬配对标签时，图片 $I_i$ 的损失为：

$$
\ell_i^{I\rightarrow T}
=-\operatorname{log}
\frac{\operatorname{exp}(s_{ii})}
{\sum_{j=1}^{B}\operatorname{exp}(s_{ij})}.
$$

**到这里仍是帮助从 CLIP 过渡的简化版本，不是原始 BLIP ITC 的完整实现。** 接下来先改变候选来源，最后再改变标签。

### 3.2 为什么引入特征队列：把过去算过的向量利用起来

当前 batch 只有 $B$ 段文本，每张图片就只有 $B$ 个当前候选。一个自然的想法是：

> 前几个 batch 的文本已经编码过了，能不能保存那些向量，这次也拿来比较？

**特征队列就是一个容量有限的历史向量缓存。** 新特征进入，最旧的特征被替换。图像与文本各有对应的队列。

| 队列保存什么？ | 队列不保存什么？ |
| --- | --- |
| 过去算好的、投影并归一化后的特征向量 | 不是把原始图片、原始文本重新放进当前 batch |
| 可直接参与相似度计算的候选特征 | 不保留供历史样本重新反向传播的完整计算图 |

以图像找文本为例，若当前有 $B=3$ 对图文，文本队列长度为 $M=6$：

| 文本候选来源 | 数量 | 本次如何获得？ |
| --- | --- | --- |
| 当前 batch | $3$ | 本次编码产生 |
| 历史队列 | $6$ | 直接读取缓存，不重新编码旧文本 |
| 合计 | $9$ | 拼接成当前的候选集合 |

这样，每张图片可以比较 $9$ 个文本候选，而不必把当前 batch 也扩大到 $9$ 对。

但缓存带来一个新问题：**旧向量由过去的模型算出，当前模型却在不断更新。若编码方式变化太快，新旧特征就更难保持一致。** 因而，BLIP 不直接把普通训练分支的特征当作队列来源，而是引入下面的慢更新副本。

### 3.3 在线与动量编码器：一份正常训练，一份缓慢跟随

先把两个名字翻译成直观含义：

| 名称 | 可以怎样理解？ | 参数怎么更新？ |
| --- | --- | --- |
| **在线编码器** | 正在正常训练的主模型；“在线”不是联网 | 反向传播 + 优化器 |
| **动量编码器** | 主模型的一份慢更新副本 | 对主模型参数做指数移动平均，即 EMA |

图像侧、文本侧及相应的对比投影层都有动量副本。副本从在线参数复制初始化，之后缓慢跟随。

记在线参数为 $\theta$，动量参数为 $\theta_m$，更新规则是：

$$
\boxed{\theta_m\leftarrow m\theta_m+(1-m)\theta}
$$

为方便理解，假设 $m=0.99$：

$$
\theta_m\leftarrow0.99\theta_m+0.01\theta.
$$

读成：**保留大部分旧副本参数，只混入一点当前主模型参数。** 这个反复加权的过程叫指数移动平均；这里平均的是参数，不是直接把图片向量求平均。官方预训练类的默认系数为 $m=0.995$，前面的 $0.99$ 只是教学例子。

> [!important] 慢更新，不等于不更新
> 动量分支不通过梯度更新，但会通过 EMA 更新。队列存储的是**动量分支产生的特征**，让历史特征的来源变化更平缓；这只能缓解新旧表示不一致，不能让旧特征永不过时。
>
> 在线编码器仍然正常训练，因此不能把这套机制理解为“冻结了 BLIP 的图像编码器”。

动量副本还有第二个用途：提供软目标。先把实际比较过程讲清楚，再在第 3.5 节解释它。

### 3.4 实际怎么比较：当前在线查询，对上当前与历史动量候选

这里会出现 **query / key**，但它们只是对比学习里的角色名，不代表 cross-attention：

- **Query（查询 / 锚点）**：这次要替谁找配对？
- **Key（候选特征）**：拿哪些向量与它比较？

以“图片找文本”为例：

| 角色 | 来自哪里？ | 在这项 ITC 计算中通过梯度更新吗？ |
| --- | --- | --- |
| 当前图片 query | 在线图像编码器及其投影层 | 是 |
| 当前文本 key | 动量文本编码器及其投影层 | 否 |
| 历史文本 key | 文本队列中的动量特征 | 否 |

**计算仍然是全局向量点积，没有让文本 token 通过 cross-attention 读取图片。** 候选停止梯度，也不意味着它们不影响训练：它们仍决定相似度与损失，从而影响在线 query 的梯度。

记在线归一化特征为 $\bar z$，动量归一化特征为 $\widetilde z$。候选下标 $j$ 遍历“当前动量特征 + 历史队列”，则：

$$
s_{ij}^{I\rightarrow T}
=\frac{(\bar z_i^I)^\top\widetilde z_j^T}{\tau}.
$$

反过来，在线文本去查找当前与历史的动量图片：

$$
s_{ij}^{T\rightarrow I}
=\frac{(\bar z_i^T)^\top\widetilde z_j^I}{\tau}.
$$

两个方向合起来，在线图像、文本编码器都能获得 ITC 梯度。

**现在再看矩阵形状就简单了：行数是当前查询数，列数是候选总数。**

$$
S^{I\rightarrow T},S^{T\rightarrow I}
\in\mathbb{R}^{B\times(B+M)}.
$$

前面的例子中，两者都是 $3\times9$：

| 方向 | 行：谁在查询？ | 列：查询哪些候选？ |
| --- | --- | --- |
| 图像找文本 | $3$ 个当前在线图片向量 | $3$ 个当前 + $6$ 个历史动量文本向量 |
| 文本找图像 | $3$ 个当前在线文本向量 | $3$ 个当前 + $6$ 个历史动量图片向量 |

因此，**反方向不是把前一个矩阵直接转置**：$3\times9$ 的转置是 $9\times3$，而不是另一个 $3\times9$。即使不考虑队列，在线与动量特征也不保证相同，不能直接套用 CLIP 对同一个方阵按行、按列分类的解释。

### 3.5 为什么引入软目标：配对唯一，不代表语义上只有一个正确描述

候选来源弄清楚了，再问：**应该要求模型给这些候选分配怎样的概率？**

原始数据只指定一个配对描述，但另一张图片的描述也可能适用。例如，为单独演示标签，暂时只展示三个文本候选：

| 候选 | 与当前狗图片的关系 | 硬配对标签 |
| --- | --- | --- |
| $T_1$：原始配对描述，讲狗在草地上跑 | 数据指定的正配对 | $1$ |
| $T_2$：另一张图片的描述，也讲狗在草地上跑 | 不是原配对，但语义可能适用 | $0$ |
| $T_3$：飞机起飞 | 明显不相关 | $0$ |

纯硬标签是 $y=[1,0,0]$。它把 $T_2$ 和 $T_3$ 都当作目标概率为零的对象，这可能产生 **false negative（假负样本）**。

BLIP 的做法是：**保留配对关系提供的硬标签，再混入动量模型对候选的判断。**

#### 动量模型的“判断”从哪里来？

与第 3.4 节相比，这次连查询图片也使用**动量图像编码器**。用动量图片向量对同一组动量文本候选打分，再做 softmax：

$$
r_{ij}^{I\rightarrow T}
=\operatorname{softmax}_j
\left(\frac{(\widetilde z_i^I)^\top\widetilde z_j^T}{\tau}\right).
$$

这个分布 $r$ 就是动量模型的软判断。文本找图片的方向同理。它不是新的人工标注，也不是 ITM 分类头的输出。

例如，假设动量模型给出：

$$
r=[0.7,0.25,0.05].
$$

将硬标签和这个分布加权混合：

$$
\boxed{\widehat y=(1-\alpha)y+\alpha r},
\qquad 0\le\alpha\le1.
$$

这里 $\alpha$ 控制相信动量判断的程度，**不是**前面 EMA 更新参数用的 $m$。为演示取 $\alpha=0.4$：

$$
\widehat y=0.6[1,0,0]+0.4[0.7,0.25,0.05]
=[0.88,0.10,0.02].
$$

| 候选 | 原硬目标 | 混合后的软目标 |
| --- | --- | --- |
| 原配对 $T_1$ | $1$ | $0.88$ |
| 语义相近的 $T_2$ | $0$ | $0.10$ |
| 不相关的 $T_3$ | $0$ | $0.02$ |

模型仍主要学习原配对，但不再被要求把其他候选的概率全部压到零。上面的数值是教学例子，不是论文中的真实样本；完整训练时，分布覆盖全部 $B+M$ 个候选。

> [!warning] 软目标不是“自动获得了正确标签”
> 动量模型可能判断错误，软目标只能缓和纯 one-hot 监督，不能保证识别所有假负样本。构造好的软目标会停止梯度，作为这次在线预测要学习的目标；不是让目标分支通过反向传播去迎合在线预测。

### 3.6 最后才合起来：在线模型预测，混合软目标监督

现在我们有两个容易混淆、但职责不同的分布：

| 符号 | 如何得到？ | 用来做什么？ |
| --- | --- | --- |
| $p$ | **在线 query** 对动量候选打分后做 softmax | 当前主模型的预测，需要通过梯度改进 |
| $r$ | **动量 query** 对同一组动量候选打分后做 softmax | 提供较平缓的模型判断 |
| $\widehat y$ | 硬配对标签 $y$ 与 $r$ 混合 | 当前训练使用的监督目标，停止梯度 |

对于一张图片，损失仍是熟悉的交叉熵，只是把 one-hot 标签换成软分布：

$$
\ell_i^{I\rightarrow T}
=-\sum_{j=1}^{B+M}
\widehat y_{ij}^{I\rightarrow T}\operatorname{log}p_{ij}^{I\rightarrow T}.
$$

**要求预测 $p$ 接近目标 $\widehat y$，不是要求 $p$ 无条件照抄动量分布 $r$。**

再对当前样本取平均，并把图像找文本、文本找图像两个方向平均，得到完整目标：

$$
\boxed{
\mathcal{L}_{\mathrm{ITC}}
=-\frac{1}{2B}\sum_{i=1}^{B}\sum_{j=1}^{B+M}
\left[
\widehat y_{ij}^{I\rightarrow T}\operatorname{log}p_{ij}^{I\rightarrow T}
+\widehat y_{ij}^{T\rightarrow I}\operatorname{log}p_{ij}^{T\rightarrow I}
\right]
}
$$

不用死记展开式，把它读成：**用混合软标签指导候选分类，两个方向都学，最后取平均。**

### 3.7 一次训练计算怎么串起来？

下面只跟踪 ITC；完整 BLIP 还会汇总 ITM 和 LM 的损失后共同更新在线参数。

1. **算在线特征**：当前图文经过在线编码器，得到可反向传播的查询向量。
2. **准备动量特征**：动量参数通过 EMA 跟随在线参数，当前图文经过动量分支，得到停止梯度的特征。
3. **准备候选**：将当前动量特征与已有队列拼接，得到各方向的 $B+M$ 个候选。
4. **准备目标**：动量 query 对候选打分，得到 $r$；与硬配对标签混合，得到 $\widehat y$。
5. **计算损失**：在线 query 对候选打分，得到 $p$；用 $\widehat y$ 计算双向交叉熵。
6. **维护缓存与更新主模型**：当前动量特征进入队列供后续 batch 使用；ITC 与其他任务的损失一起通过优化器更新在线模型。队列本身不是可学习参数。

> [!summary] 和 CLIP 相比，到底变了什么？
> **没变的主干**：独立编码 → 全局向量相似度 → 候选 softmax → 双向交叉熵。
>
> **增加的机制**：队列扩充候选；动量副本提供变化更平缓的候选特征与软判断；硬软标签混合缓和唯一配对监督。
>
> 这里既没有 cross-attention，也没有把 ITC 改成 SigLIP 式的逐对 sigmoid 二分类。

**实现细节放在理解机制之后看：** 官方预训练类默认投影维度为 $256$、队列长度为 $57{,}600$。温度 `self.temp` 初始化为 $0.07$，并限制在 $0.001$--$0.5$；它直接学习温度，不是像 CLIP 那样存储 `logit_scale` 再取指数。这些是实现设置，不是理解 ITC 必须先背下来的定义。参见 [官方 ITC、动量分支与队列实现](https://github.com/salesforce/BLIP/blob/main/models/blip_pretrain.py)。

## 4. ITM：把图文放在一起，判断是否真正匹配

> [!abstract] 先抓住主线：不只是换一种分类损失
> **ITC 先独立编码，再比较两个全局向量；ITM 让文本读取当前图片的视觉 token，再判断这一对是否匹配。**
>
> - **计算这条线**：希望进一步检查动作、场景等细节 → 让图文在编码过程中交互 → 得到依赖当前配对的融合表示 → 判断 matched / unmatched。
> - **样本这条线**：只学明显错配太容易 → 用 ITC 找出更容易混淆的候选 → 抽取难负例 → 只对选中的配对运行较昂贵的融合编码。
>
> 下面先解释“怎么一起看”，再解释“训练时给它看哪些配对”。

### 4.1 ITC 已经会匹配，为什么还需要 ITM？

还是同一张图片：**一只狗在草地上跑。**

| 候选描述 | 需要检查什么？ |
| --- | --- |
| “一只狗在草地上跑。” | 动物、动作与场景是否吻合 |
| “一只狗在沙发上睡觉。” | 都有狗，但动作和场景不同 |
| “一架飞机正在起飞。” | 连主要内容都不同 |

ITC 先把图片、文本各自压成全局向量，再比较相似度。ITM 则增加一条计算路径：**编码这句话时，允许它直接读取当前图片的视觉信息。**

| 对比 | ITC | ITM |
| --- | --- | --- |
| 文本编码时是否读取当前图片？ | 否 | 是，通过 cross-attention |
| 最后拿什么打分？ | 两个独立全局向量 | 当前图文对的融合表示 |
| 同一句话换一张图 | 独立文本向量不变，相似度可能变 | 融合表示本身就可能变 |

这里不是说 ITC 完全学不到细节，或 ITM 一定能判断正确。**区别在于有没有针对当前图文配对进行 token 级交互，而不是把“对齐”和“理解”划成绝对的能力边界。**

### 4.2 图文怎么一起看：文本提取上下文，再读取视觉特征

先回忆第 2.4 节，但这次跟着数据走：

1. **图片先编码**：ViT 输出整串视觉 token，不只是一个全局 CLS 向量。
2. **文本内部交流**：双向 self-attention 让词语利用完整句子的上下文。
3. **文本读取图片**：cross-attention 用文本状态作为 Query、视觉特征作为 Key / Value，更新文本表示。
4. **汇总配对信息**：取特殊起始 token `[Encode]` 的输出，作为这对图文的融合表示。

文本侧每层的主体是：**双向 self-attention → cross-attention → FFN**；这是省略残差、LayerNorm 等细节后的概括。

> [!note] 这里的 Query / Key 才是 attention 里的角色
> 第 3 节 ITC 的 query / key 只是“查询向量 / 候选向量”的叫法，做的是全局相似度比较。这里的 cross-attention 则真的让文本位置对视觉 token 分配权重，并读取视觉 Value。不要因为名字相同就把两条计算路径混在一起。

用一个式子记住最终结果：

$$
h_{ij}^{\mathrm{fuse}}
=\operatorname{MED}_{\mathrm{enc}}(T_j,H_i^I)_{\mathrm{Encode}}
\in\mathbb{R}^{d_t}.
$$

读成：**让文本 $T_j$ 看过图片特征 $H_i^I$，再取起始位置的输出。** 它同时依赖图片与文本，不是单独一句话的固定 embedding。

这也解释了计算成本：图像特征可以复用，但每个选中的图文配对仍需进行对应的融合计算。检索时可以先用 ITC 快速召回少量候选，再用 ITM 精细重排，而不对整个候选库逐对融合。

### 4.3 标签从哪里来：正例沿用配对，负例来自错配

ITM 不需要额外人工标注一套“匹配 / 不匹配”数据。它利用当前 batch 中已知的图文对应关系：

| 图片 | 文本 | 训练标签 |
| --- | --- | --- |
| 狗在草地上跑 | 这张图原本的配对描述 | matched，$y=1$ |
| 狗在草地上跑 | 从其他样本选来的描述 | unmatched，$y=0$ |
| 从其他样本选来的图片 | 当前狗图片原本的描述 | unmatched，$y=0$ |

负例可以通过**换文本**或**换图片**构造，但有一个问题：如果总换成“飞机起飞”，模型可能只区分主要对象就能通过训练。

为了增加有价值的练习，BLIP 会更倾向选择“看起来挺像，但不是已知正配对”的候选，也就是 **hard negatives（难负例）**。

注意，这里的标签来自数据配对规则，不是真理：原始描述可能有噪声，错配描述也可能恰好适用，形成假负样本。

### 4.4 难负例怎么选：ITC 帮忙出题，ITM 练习判断

对狗图片而言：

- “飞机起飞”通常是比较容易的负例。
- “狗在沙发上睡觉”可能更容易混淆，更值得仔细检查。

BLIP 使用 ITC 的相似度来指导采样：**在当前 batch 内，排除已知正配对，让相似度高的错配更容易被抽到。**

把图像 $I_i$ 的负文本采样分布简化写为：

$$
P(j\mid i,\mathrm{negative})
=\frac{\operatorname{exp}(s_{ij}^{I\rightarrow T})}
{\sum_{k\ne i}\operatorname{exp}(s_{ik}^{I\rightarrow T})},
\qquad j\ne i.
$$

这里的候选下标只遍历**当前 batch**，不是把第 3 节历史队列中的所有特征都拿来做 ITM 融合；公式省略了实现中的数值稳定项。反方向也为当前文本抽取负图片。

> [!important] “更容易抽到”不等于“每次取最大分数”
> 这是按相似度引导的随机采样，不是固定选 top-$1$。ITC 负责提供出题依据，ITM 仍要通过自己的融合表示和分类头判断配对。
>
> 采样过程停止梯度，因此没有“ITM loss → 离散采样 → ITC 分数”的直接可微路径；共享编码器仍可分别收到各自任务的梯度。

官方预训练实现从 $B$ 对原始图文构造：

| 配对类型 | 数量 |
| --- | --- |
| 原始图片 + 原始配对文本 | $B$ |
| 采样负图片 + 当前文本 | $B$ |
| 当前图片 + 采样负文本 | $B$ |
| 合计 | $3B$ |

例如，当前 batch 有 $B=4$ 对图文，则 ITM 计算 $12$ 个配对实例的损失，**不是把全部 $16$ 个交叉组合都进行融合编码**。这些实例不保证全部互不重复；重点是按正例、两类负例组成训练集合。

### 4.5 最后再看损失：融合表示如何变成匹配判断？

把第 4.2 节得到的融合表示送进线性分类头：

$$
u_{ij}=W_{\mathrm{ITM}}h_{ij}^{\mathrm{fuse}}+b_{\mathrm{ITM}}
\in\mathbb{R}^{2}.
$$

这个向量只有两个分数，分别对应 **unmatched** 与 **matched**，而不是对应 batch 中的候选编号。对这两个分数做 softmax，取 matched 的输出：

$$
\pi_{ij}
=\operatorname{softmax}(u_{ij})_{\mathrm{matched}}.
$$

对一对图文，交叉熵可以等价地写成：

$$
\ell_{ij}^{\mathrm{ITM}}
=-y_{ij}\operatorname{log}\pi_{ij}
-(1-y_{ij})\operatorname{log}(1-\pi_{ij}).
$$

| 标签 | 损失化简 | 希望模型怎么改？ |
| --- | --- | --- |
| 正例，$y_{ij}=1$ | $-\operatorname{log}\pi_{ij}$ | 提高 matched 输出 |
| 负例，$y_{ij}=0$ | $-\operatorname{log}(1-\pi_{ij})$ | 降低 matched 输出 |

例如，负例被预测为 $\pi_{ij}=0.9$，损失约为 $2.303$；降到 $0.1$ 时，损失约为 $0.105$。**越自信地把负例判成正例，惩罚越大。** 最后对构造出的 $3B$ 个配对实例取平均。

官方代码采用**两个 logits 的 softmax + CE**；上面的二分类展开与它等价，不表示实现采用了单 logit 的 BCE。

### 4.6 和 SigLIP 有什么关系？先分清监督形式与打分结构

“它们都判断正负，所以是不是同一个方法？”这个联想抓住了监督形式，却还要看分数怎么来：

| 方法 | 分数从哪里来？ | 分类在问什么？ |
| --- | --- | --- |
| CLIP / BLIP 的 ITC | 双塔独立表示的相似度 | 在候选集合里，哪个应该配对？ |
| SigLIP | 双塔独立表示的相似度，加尺度与 bias | 这一对是正配对吗？ |
| BLIP 的 ITM | 图文交互后的融合表示 + 分类头 | 这一对是正配对吗？ |

**SigLIP 与 ITM 都有逐对正负二分类的思想，但只有这里的 ITM 使用图文融合来打分。** 单 logit sigmoid 与两个 logits softmax 的差别不是最本质的区别；后者可写成对两个 logits 之差做 sigmoid。更多对照见 [[03-SigLIP：从逐对二分类到共享语义空间|SigLIP 笔记]]。

> [!summary] 跟着一对图文走完 ITM
> **原始配对作正例，ITC 引导抽取难负例 → 图片提供视觉 token → 文本双向编码并通过 cross-attention 看图 → 取 `[Encode]` 融合表示 → 匹配二分类 → 更新使用到的在线参数。**
>
> ITC 与 ITM 不是把同一件事重复做两遍：前者适合快速比较与召回，后者提供逐对交互判断，可用于重排与 CapFilt 过滤。

参见 [官方 ITM、负例采样与分类实现](https://github.com/salesforce/BLIP/blob/main/models/blip_pretrain.py)。

## 5. LM：给定图片和前缀，预测下一个 token

> [!abstract] 先抓住主线：从“判断给定句子”到“自己写出句子”
> **ITM 已经拿到了完整描述，输出匹配状态；LM 还没有完整描述，要看着图片和已有前缀，预测接下来写什么。**
>
> 想让模型自己写描述 → 把描述拆成逐 token 预测任务 → 预测时不能偷看未来文本 → 使用因果 self-attention，同时通过 cross-attention 读取图片 → 对真实下一个 token 计算损失。
>
> 接下来先讲答案从哪里来，再区分训练和生成，最后看损失公式。

### 5.1 不需要新的人工标注：配对描述本身就是答案

还是同一对训练数据：图片是狗在草地上跑，文本是 `a dog running on grass`。

只要把这段描述的前缀当输入，紧随其后的 token 当目标，就能构造生成训练。下面为方便理解按单词展示；实际 tokenizer 可能把一个单词拆成多个 subword token。

| 模型可见的文本前缀 | 还可以读取什么？ | 要预测什么？ |
| --- | --- | --- |
| `[Decode]` | 整张图片的视觉特征 | `a` |
| `[Decode] a` | 整张图片的视觉特征 | `dog` |
| `[Decode] a dog` | 整张图片的视觉特征 | `running` |
| `[Decode] a dog running` | 整张图片的视觉特征 | `on` |
| `[Decode] a dog running on` | 整张图片的视觉特征 | `grass` |
| `[Decode] a dog running on grass` | 整张图片的视觉特征 | 结束 token |

起始标记负责告诉模型“开始写”，结束 token 负责让模型学会“写完了”。**目标包含结束 token，但不要求模型预测输入中的起始标记。** `[Decode]` 是论文的功能记法，官方 tokenizer 对应字符串为 `[DEC]`。

### 5.2 网络怎么完成预测：读前缀、读图片、选 token

以预测 `running` 为例，文本侧每层的主体可以理解为：

| 模块 | 在做什么？ |
| --- | --- |
| **Causal self-attention** | 读取已有文本 `a dog`，不能读取后面的真实答案 |
| **Cross-attention** | 用文本状态读取整串视觉 token，利用图片信息 |
| **FFN** | 进一步处理结合了文本上下文与视觉信息的表示 |
| **最终词表输出头** | 给词表中的 token 分配分数，经 softmax 得到下一 token 分布 |

前三项在文本 Transformer 层中重复，最后才使用词表输出头；表格省略了残差与 LayerNorm 等细节。

生成第 $t$ 个 token 时，模型计算：

$$
p_\Theta(t_t\mid t_{<t},I).
$$

| 符号 | 意思 |
| --- | --- |
| $t_t$ | 当前要预测的 token |
| $t_{<t}$ | 它前面的文本 token，即前缀 |
| $I$ | 当前图片提供的条件 |
| $\Theta$ | 参与预测的模型参数 |

> [!note] 文本侧是 decoder，不代表整个模型是 GPT 式 decoder-only
> BLIP 的这条路径是**视觉 encoder + 图像条件文本 decoder**。文本 decoder 使用因果 self-attention，还通过 cross-attention 读取独立视觉编码器的输出。
>
> 与 ITM 相比，不能只把“匹配分类头”换成“词表头”就结束，还要限制未来文本可见性；原始 MED 的 encoder 与 decoder 也使用不同参数的 self-attention，其他部分按第 2.6 节的策略共享。

### 5.3 为什么需要 causal mask：防止训练时偷看答案

训练数据中明明已经有完整句子，为什么还要遮住未来？

因为我们要练习的是：**看见 `a dog` 和图片后，能否预测 `running`。** 如果预测位置能读取输入里后面的真实 `running`，模型就可能利用答案泄漏，而不必学会实际生成时需要的预测能力。

**Causal mask（因果掩码）**限制每个文本位置只能读取该位置及之前的输入，不能读取之后的位置。

| 输出所在的输入位置 | 该位置可读取的文本输入 | 用该位置输出预测 |
| --- | --- | --- |
| `[Decode]` | `[Decode]` | `a` |
| `a` | `[Decode] a` | `dog` |
| `dog` | `[Decode] a dog` | `running` |

这也解释了“输入与目标错开一位”的含义：**`dog` 位置的输出负责预测后面的 `running`，不是把当前位置输入的 `dog` 再复述一次。**

因果限制仅针对文本。每个预测位置都可以读取整张图片的视觉特征，**不是把图像 patch 也按顺序逐个开放**。

### 5.4 Teacher forcing：训练用真实前缀，生成用自己写的前缀

**Teacher forcing** 的意思是：训练时，用真实描述提供前缀，而不是必须把模型刚刚猜出的 token 喂回去。

例如，即使模型在某个位置把 `dog` 猜成了 `cat`，训练后续位置预测 `running` 时，所用前缀仍然是数据中的 `a dog`。

| 对比 | 训练时 | 实际生成时 |
| --- | --- | --- |
| 前缀从哪里来？ | 配对描述中的真实 token | 模型已经生成的 token |
| 有没有真实下一 token 可作监督？ | 有 | 没有 |
| 文本位置如何计算？ | 在 causal mask 下，可并行计算多个位置 | 通常逐步选出 token，再继续生成 |
| 何时结束？ | 真实结束 token 也是训练目标 | 生成结束 token，或达到长度限制等停止条件 |

> [!important] 自回归目标，不等于训练必须逐词调用模型
> 训练时，真实前缀都已经在句子里，可以一次送入整段文本，再用 causal mask 限制各位置可见范围，并行计算各位置的 next-token loss。
>
> 生成时没有后续真实文本，才需要根据自己生成的结果继续下一步。因而生成中的早期错误可能影响后面的内容。

官方实现会在损失计算时将输出 logits 与目标文本错开一个位置，完成这种 next-token 对齐；不应误以为需要在外部和模型内部各右移一次。

### 5.5 最后看基础损失：提高真实下一 token 的概率

每个预测位置都在词表 $\mathcal{V}$ 上做分类。假设真实目标是 `running`：

$$
p_\Theta(\text{running}\mid\text{a dog},I)=0.2.
$$

暂时忽略 label smoothing，这个位置的损失是：

$$
\ell_t^{\mathrm{LM}}=-\operatorname{log}0.2\approx1.609.
$$

如果模型利用图片与前缀，把正确 token 的概率提高到 $0.8$，损失就降到约 $0.223$。**训练用完整概率分布计算损失，不需要先把模型输出变成一个离散单词再判断对错。**

整段描述的条件概率可以写成各步条件概率的乘积：

$$
p_\Theta(T\mid I)
=\prod_{t=1}^{L}p_\Theta(t_t\mid t_{<t},I),
$$

其中目标序列包括结束 token。取负对数后，乘积变成各位置损失之和。

再把 batch 中所有有效目标位置汇总。记这些位置的集合为 $\Omega$，数量为 $N_{\mathrm{tok}}$，基础损失为：

$$
\boxed{
\mathcal{L}_{\mathrm{LM}}
=-\frac{1}{N_{\mathrm{tok}}}
\sum_{(i,t)\in\Omega}
\operatorname{log}p_\Theta(t_{i,t}\mid t_{i,<t},I_i)
}
$$

读成：**对所有真实下一 token 的负对数概率取平均。** 为了凑齐长度而添加的 padding 不算有效目标；官方实现把这些目标位置设为忽略值。

虽然预测的是文字，损失仍能沿着**词表预测 → 文本 decoder → cross-attention → 视觉特征 → ViT** 回传。因此，LM 也能训练在线图像编码器；详细梯度路径见第 6 节。

### 5.6 Label smoothing：答案仍来自真实文本，不来自动量教师

前一节用了 one-hot 目标：正确 token 的目标概率为 $1$，其他 token 为 $0$。原始 BLIP 的 LM 还会使用 **label smoothing（标签平滑）**：把少量目标概率均匀分给整个词表，避免目标要求模型对唯一 token 过度确信。

原论文与官方实现使用 $\varepsilon=0.1$。记真实 token 的 one-hot 目标为 $y_t$，平滑后：

$$
\widetilde y_{t,v}
=(1-\varepsilon)y_{t,v}+\frac{\varepsilon}{\lvert\mathcal{V}\rvert}.
$$

所以：

- 正确 token 的目标概率是 $1-\varepsilon+\varepsilon/\lvert\mathcal{V}\rvert$。
- 其余每个 token 的目标概率是 $\varepsilon/\lvert\mathcal{V}\rvert$。

每个位置实际计算：

$$
\ell_t^{\mathrm{LM}}
=-\sum_{v\in\mathcal{V}}
\widetilde y_{t,v}\operatorname{log}p_{t,v},
$$

然后仍对有效目标位置取平均。

| 对比 | ITC 的软目标 | LM 的标签平滑 |
| --- | --- | --- |
| 在给谁分配概率？ | 图文对比候选 | 词表中的 token |
| 额外概率怎么分配？ | 参考动量模型的候选分布 | 均匀分给整个词表 |
| 真实监督保留在哪里？ | 与原始配对标签混合 | 与真实下一 token 的 one-hot 标签混合 |

**两者都会让目标不再是纯 one-hot，但来源不同。LM 这里没有用动量模型提供下一词答案。**

### 5.7 三种任务终于可以放在一起看了

| 目标 | 模型拿到什么？ | 分类的“类别”是什么？ | 标签从哪里来？ |
| --- | --- | --- | --- |
| ITC | 独立图文特征与候选集合 | 不同候选样本 | 配对关系 + 动量软判断 |
| ITM | 一对完整图片和文本 | matched / unmatched | 原始配对与采样错配 |
| LM | 图片与文本前缀 | 词表 token | 真实下一 token，再做标签平滑 |

因此，**都能使用交叉熵，不代表在做同一个任务。**

另外，不要把 BLIP 的 LM 与下面两种设置混淆：

- **MLM（掩码语言建模）**：遮住部分文本位置，通常允许利用左右文恢复内容；这不是这里的从左到右生成目标。
- **不以图像为条件的文本 LM**：只利用文本前缀；BLIP 这里还利用图片。所谓“不以图像为条件”不代表连文本前缀也没有。

> [!summary] 跟着同一句描述走完 LM
> **取配对描述 → 把前缀与下一 token 对齐 → 用 causal mask 防止偷看未来 → 文本 decoder 读取前缀和图片 → 输出词表分布 → 对真实目标做标签平滑并计算交叉熵 → 更新使用到的在线参数。**
>
> 训练用真实前缀，可并行计算多个位置；生成用自己写出的前缀，逐步继续。能生成也不等于不会幻觉，训练目标并不保证每个输出 token 都符合画面。

参见 [论文第 3.2 节](https://arxiv.org/abs/2201.12086)与[官方 LM 损失实现](https://github.com/salesforce/BLIP/blob/main/models/med.py)。

## 6. 梯度与参数更新：三个目标共同塑造同一套能力

> [!abstract] 这一节不再增加任务，只回答“学到哪里去了？”
> 前面已经知道 ITC、ITM、LM 分别预测什么。现在把它们放回同一轮训练：**算出三个损失 → 沿各自使用的路径回传 → 共享参数汇总梯度 → 优化器更新在线模型。**
>
> 先看哪些模块被使用，再跟踪一次预测错误，最后才用梯度公式总结。动量副本与队列的机制见第 3 节，这里只区分它们与在线参数的更新方式。

### 6.1 联合训练：不是练完对齐，才开始练匹配与生成

对于当前 batch，BLIP 按不同运行模式计算 ITC、ITM、LM，最后把三个损失相加：

$$
\boxed{
\mathcal{L}_{\mathrm{BLIP}}
=\mathcal{L}_{\mathrm{ITC}}
+\mathcal{L}_{\mathrm{ITM}}
+\mathcal{L}_{\mathrm{LM}}
}
$$

这里的“联合”有两层含义：

- **同一轮预训练共同优化**：不是先单独训练完 ITC，再训练 ITM，最后训练 LM。
- **部分模块确实共享**：不是三个互不相关的模型，只把最后的损失值打印在一起。

在线 ViT 算出的视觉 token 可以供多个任务复用；文本侧按不同模式计算相应输出。动量视觉分支另有停止梯度的前向计算，不能与在线视觉计算混为一谈。

这里描述的是**一次模型预训练内部的组织方式**。第 7 节 CapFilt 的“先训练、再处理数据、再训练新模型”是另一个更大的阶段流程。

### 6.2 先认清结构：哪些模块公用，哪些模块各自负责？

不用一开始就背完整参数表，先把在线模型分成三组：

| 模块组 | 包含什么？ | 谁在使用？ |
| --- | --- | --- |
| 三个任务共同使用 | 在线 ViT、文本公共 embedding 与 FFN 等 | ITC、ITM、LM |
| 部分任务共享 | encoder 的双向 self-attention；图文 cross-attention | 前者用于 ITC / ITM，后者用于 ITM / LM |
| 任务专用部分 | decoder 的因果 self-attention，以及各任务专用输出参数 | 按任务分别使用 |

“任务输出头各司其职”不代表所有底层权重都独立：例如 LM 输出头存在公共绑定权重时，同一份权重仍按共享关系累计梯度。具体共享策略见第 2.6 节。

> [!tip] 判断一个 loss 会不会训练某个参数，先问一个问题
> **这个预测是否通过一条没有被停止梯度或离散操作切断的计算路径，依赖该参数？**
>
> 不是看“最后输出的是图片还是文字”，也不是看“这个模块名字属于哪个模态”。下面用 LM 举例。

### 6.3 跟着一次错误走：预测的是文字，为什么 ViT 也会学？

图片是狗在草地上跑，给定真实前缀 `a dog`，目标是 `running`。假设模型给 `running` 的概率太低，就会产生较大的 LM 损失。

这个预测依赖怎样的前向计算？

1. **ViT 提供视觉特征**：把图片编码为视觉 token。
2. **Cross-attention 读取视觉信息**：文本状态利用这些 token 更新自己的表示。
3. **Decoder 与词表头做预测**：根据图像信息和文本前缀，输出下一 token 分布。

反向传播沿这些依赖关系往回计算梯度：

> **LM loss → 词表预测 → 文本 decoder → cross-attention → 视觉 token → 在线 ViT。**

因此，损失既可以调整“文本侧如何读取图片”，也可以调整“图像侧提供什么特征”。**不能因为最终预测文字，就认为只训练文本模型。**

同样的方法可以检查其他目标：

| 损失 | 主要回传路径 |
| --- | --- |
| ITC | 相似度 → 在线全局特征与投影 → 对应在线编码器 |
| ITM | 匹配分类头 → 融合表示 → 文本 encoder 与 cross-attention → 在线视觉特征与 ViT |
| LM | 词表输出头 → 条件 decoder 与 cross-attention → 在线视觉特征与 ViT |

这表示计算图允许梯度回传，不保证某个样本的每个参数梯度都非零，也不保证模型一定学会正确使用每个视觉细节。

**ITC 还要特别区分方向：** 图像找文本时，文本候选是停止梯度的动量特征，这条路径主要训练在线图像 query；文本找图像时，在线文本 query 才获得相应的 ITC 梯度。双向合起来，在线图像与文本编码器都能学习。

### 6.4 共享参数收到不同意见，怎么办？先把梯度相加

以在线 ViT 为例：

- ITC 希望它提供适合全局对齐的特征。
- ITM 希望它提供有助于判断当前配对的特征。
- LM 希望它提供有助于预测描述 token 的特征。

不是给同一份参数轮流指定三个新值，而是让三个损失对它的梯度相加，再交给优化器处理。

记一份共享参数为 $\theta_s$：

$$
\nabla_{\theta_s}\mathcal{L}_{\mathrm{BLIP}}
=\nabla_{\theta_s}\mathcal{L}_{\mathrm{ITC}}
+\nabla_{\theta_s}\mathcal{L}_{\mathrm{ITM}}
+\nabla_{\theta_s}\mathcal{L}_{\mathrm{LM}}.
$$

哪个任务不使用该参数，相应项就是零。用普通梯度下降作直观示意：

$$
\theta_s\leftarrow\theta_s-\eta\nabla_{\theta_s}\mathcal{L}_{\mathrm{BLIP}},
\qquad\eta>0.
$$

这只是帮助理解的更新示意，不代表官方优化器只有这一行。不同任务的梯度可能相互支持，也可能部分抵消；**联合优化不保证每一步三个任务的损失都同时下降。**

有了这个认识，再查完整的在线参数分工表：

| 参数部分 | ITC | ITM | LM |
| --- | --- | --- | --- |
| 在线视觉编码器 ViT | 是，通过在线图像特征 | 是，通过视觉 token | 是，通过视觉 token |
| 文本公共 embedding、FFN 等 | 是 | 是 | 是 |
| 文本 encoder 的双向 self-attention | 是 | 是 | 否 |
| 文本 decoder 的 causal self-attention | 否 | 否 | 是 |
| 共享 cross-attention | 不启用 | 是 | 是 |
| ITC 图像、文本投影层及温度 | 是 | 不通过负例采样反传 | 否 |
| ITM 分类头 | 否 | 是 | 否 |
| LM 输出头 | 不直接使用该头 | 不直接使用该头 | 是；公共绑定权重按共享关系累计梯度 |

> [!warning] 使用一个结果，不一定能沿它反向传播
> ITM 虽然参考 ITC 分数抽取难负例，但离散采样在无梯度路径中完成。不存在“ITM loss → 负例采样概率 → ITC 温度”的直接可微路径。
>
> ITM 仍能通过被选配对的融合编码训练共享模块。这与“不能穿过采样操作回传”并不矛盾。

### 6.5 不是所有东西都由优化器更新：主模型、副本与缓存要分开

| 对象 | 怎样变化？ | 可以怎样理解？ |
| --- | --- | --- |
| 在线模型参数 | 由总损失反向传播，再由优化器更新 | 直接学习任务的主模型 |
| 动量模型参数 | 通过 EMA 跟随在线参数 | 主模型的慢更新副本 |
| 特征队列 | 写入当前动量特征，替换最旧特征 | 保存历史候选的缓存，不是可学习参数 |

动量更新仍是第 3 节的公式：

$$
\theta_m\leftarrow m\theta_m+(1-m)\theta.
$$

官方预训练类默认 $m=0.995$。动量分支不由优化器反传更新，不等于参数永远不变；队列中的旧向量也不会因为副本更新就自动重新计算。

因此，原始 BLIP **会训练在线视觉编码器**。不要把它与 [BLIP-2](https://arxiv.org/abs/2301.12597) 冻结视觉编码器和大语言模型、训练桥接模块的设置混在一起。

### 6.6 最后用一个公式总结：预测概率减去目标概率

现在再看交叉熵的梯度，就有了明确对象。对 softmax logits $u$、预测分布 $p$ 和固定的归一化目标分布 $y$，忽略平均系数：

$$
\frac{\partial\ell}{\partial u_j}=p_j-y_j.
$$

| 预测与目标的关系 | 对该 logit 的梯度 | 单独看该 logit 的梯度下降倾向 |
| --- | --- | --- |
| $p_j<y_j$ | 负 | 提高 logit |
| $p_j>y_j$ | 正 | 降低 logit |
| $p_j=y_j$ | 零 | 此项没有直接纠偏信号 |

三个任务的差别在于 $p$ 与 $y$ 分别代表什么：

| 任务 | 对应梯度形式 | 概率与目标的对象 |
| --- | --- | --- |
| ITC | $p_{ij}-\widehat y_{ij}$ | 图文候选的预测分布与混合软目标 |
| ITM | $\pi_{ij}-y_{ij}$ | matched 类输出与正负标签 |
| LM | $p_{t,v}-\widetilde y_{t,v}$ | 词表预测与标签平滑后的真实目标 |

例如，某个非配对文本的 ITC 软目标是 $0.10$，但当前预测只有 $0.03$，则该项梯度为 $-0.07$，直接倾向是提高它的 logit。**所以不能说 BLIP 的所有非对角线候选都一定被推远。**

这里分析的是对 logit 的直接梯度；实际更新的是共享网络参数。结合第 6.4 节的梯度汇总，一次更新后每个样本的分数不保证都按单项分析的方向变化。

> [!summary] 一次更新的完整心智模型
> **同一批图文按不同模式计算三个损失 → 沿各自可微路径回传 → 共享参数梯度相加 → 优化器更新在线模型。** 动量副本通过 EMA 跟随，队列通过写入与替换维护。
>
> “理解与生成共同训练”的含义，是不同任务确实影响了部分相同的参数，而不是只把三个输出并排展示。

参见 [官方预训练模型](https://github.com/salesforce/BLIP/blob/main/models/blip_pretrain.py)与[官方预训练循环](https://github.com/salesforce/BLIP/blob/main/pretrain.py)。

## 7. CapFilt：用已经学会的能力，改进下一轮训练数据

> [!abstract] 注意：这里从“更新模型”切换到“改进数据”
> 前面讲的是如何用 ITC + ITM + LM 训练一个 MED。接下来问：**既然模型能写描述，也能判断匹配，能不能反过来改善网上的图文数据？**
>
> **网络文本有噪声 → 用生成能力补写描述 → 用匹配能力筛选新旧描述 → 得到改进后的训练集 → 预训练一个新的 BLIP 模型。**
>
> 这叫 **CapFilt：Captioning and Filtering（生成描述与过滤）**，是离线的数据处理流程，**不是加到总损失里的第 $4$ 个 loss**。

### 7.1 先看问题：更多配对，不一定是更好的监督

网络图片的配套文字可能描述画面，也可能只是网页标题、广告或文件名。

例如，图片明明是狗在草地上跑，网页文本却是：

> “my weekend diary”

这段文字不是完全没有网页语境，却没有明确告诉模型图片里的对象、动作和场景。继续扩大类似数据的数量，不等于同时改善监督质量。

于是可以安排两个角色：

| 角色 | 做什么？ | 利用前面哪种能力？ |
| --- | --- | --- |
| **Captioner：描述生成器** | 看图片，补写新的 caption | 图像条件 LM 的生成能力 |
| **Filter：过滤器** | 判断一段描述是否与图片匹配 | ITM 的匹配判断能力 |

先把它们当作“能写”和“能判”的两个工具，下一节跟踪它们怎样处理这张图；第 7.3 节再解释它们从哪里训练出来。

### 7.2 跟着一张图片走：补写，但不盲信新描述

对于狗图片，假设 captioner 写出了：

> “a dog running on grass”

现在同一张图有两种描述来源：

| 来源 | 教学例子 |
| --- | --- |
| 原始网页文本 | `my weekend diary` |
| 模型生成文本，即 synthetic caption | `a dog running on grass` |

接下来，filter **分别检查原始描述和生成描述**。如果它拒绝原始文本、接受生成文本，新数据里就保留“图片 + 生成描述”这个配对。

这是教学情景，不代表 filter 对这些具体文本必然作出上述判断。尤其要注意，生成器也可能写错，例如把狗写成猫，所以不能省略对生成描述的过滤。

所有可能的保留结果是：

| 原始描述 | 生成描述 | 新训练集保留什么？ |
| --- | --- | --- |
| 通过 | 通过 | 两个配对都保留 |
| 不通过 | 通过 | 只保留生成描述配对 |
| 通过 | 不通过 | 只保留原始描述配对 |
| 不通过 | 不通过 | 这张网络图片没有保留下来的这两类配对 |

> [!important] 不是替换规则，而是分别生成、分别筛选
> CapFilt 不是“一律用新描述覆盖旧描述”，也不是“生成出来的文本天然可信”。同一张图片可以保留多个描述，也可能一个都不保留。

### 7.3 这两个工具从哪里来：先预训练，再分别微调

Captioner 与 filter 不是从零突然出现，也不是联合预训练网络里的两个 head 在每个 batch 里当场互相打分。

论文先训练一个具备对齐、匹配和生成能力的 MED，然后从同一个预训练模型初始化两个用途不同的模型，**分别端到端微调**：

| 模块 | 初始化来源 | 微调数据 | 微调目标 | 处理网络数据时做什么？ |
| --- | --- | --- | --- | --- |
| Captioner | 初始预训练 MED | COCO | LM | 为每张网络图片生成一条新描述 |
| Filter | 同一个初始预训练 MED | COCO | ITC + ITM | 用 ITM head 判断新旧描述，拒绝 unmatched 配对 |

这意味着流程仍然使用人工标注监督，不能把“模型自动补写和筛选”理解成完全不依赖人工标注数据。

也要区分：**filter 微调时使用 ITC + ITM，执行这里的保留 / 拒绝决定时依据 ITM 判断。** 它不是只用 ITC 余弦相似度代替前面学过的融合匹配。

### 7.4 把时间顺序串起来：训练能力、加工数据、训练新模型

| 阶段 | 输入 | 做什么？ | 产物 |
| --- | --- | --- | --- |
| 初始预训练 | 人工标注图文 + 原始网络图文 | ITC + ITM + LM 联合训练 | 初始 MED |
| 工具微调 | 初始 MED + COCO | 分别微调生成器和过滤器 | 独立的 captioner / filter |
| 离线数据处理 | 网络图片与原始文本 | 生成新描述，分别筛选新旧描述 | 保留下来的网络图文配对 |
| 新模型预训练 | 保留配对 + 人工标注图文 | 用改进后的数据重新预训练 | 新的 BLIP 模型 |

> [!tip] “自举”具体发生在哪里？
> **先用现有数据学出能力，再用这些能力改进后续训练数据。** 模型的输出成为后续训练的部分监督来源，因此不只是“数据训练模型”的单向过程。
>
> 这不意味着每个 mini-batch 都要重写整个数据集，也不意味着必须无限循环生成与重训。

“训练新模型”不是直接拿生成教师的整套 BLIP checkpoint 接着训练。不过，新模型的视觉与文本骨干仍可按论文设置使用 ImageNet 预训练 ViT、BERT 初始化，**不是所有参数都从随机值开始**。论文也比较了继续训练旧模型，其实验没有显示比重新训练新模型更有优势。

理解流程之后，再把新数据集写成公式。记：

- $\mathcal{D}_h$：人工标注图文数据。
- $\mathcal{D}_w$：原始网络图文配对。
- $\mathcal{D}_s$：生成描述构成的合成配对。
- $\operatorname{keep}(I,T)\in\{0,1\}$：filter 的保留决定。

则：

$$
\mathcal{D}_{\mathrm{boot}}
=\mathcal{D}_h
\cup\{(I,T)\in\mathcal{D}_w:\operatorname{keep}(I,T)=1\}
\cup\{(I,T)\in\mathcal{D}_s:\operatorname{keep}(I,T)=1\}.
$$

读成：**人工标注数据 + 通过过滤的原始网络配对 + 通过过滤的合成配对。** 并集在这里表示汇集训练样本，不要求每张图片只对应一句话。参见 [论文第 3.3 节与第 6 节](https://arxiv.org/abs/2201.12086)。

### 7.5 为什么独立微调：尽量避免生成器与过滤器一起相信同一个错误

你可能会问：第 6 节刚说共享参数有好处，为什么这里又要分开？

因为两个阶段解决的问题不同：

| 阶段 | 主要诉求 |
| --- | --- |
| MED 联合预训练 | 让对齐、理解与生成共同影响部分共享参数 |
| CapFilt 的生成与筛选 | 希望过滤器能识别生成器的错误，而不是一味认同它 |

例如，如果生成器容易把某类狗看成猫，紧密共享参数的过滤器也可能有相同倾向，结果是错误描述被保留下来。这就是作者用 **confirmation bias（确认偏差）** 解释共享版本表现下降的直觉。

论文采用的做法是从同一 MED 初始化后分别端到端微调，而不是在这一阶段继续绑住两者的参数。**这是有实验支持的作者解释，不是证明分开训练就能消除所有相关错误。**

### 7.6 为什么生成时还要保留多样性：不只反复写最常见的句子

如果所有图片都得到很笼统、很相似的描述，新数据可能没有增加多少语义信息。CapFilt 因此还关心：**如何生成有变化的描述，同时把明显不可靠的内容筛掉？**

原论文生成网络描述时使用 **nucleus sampling（核采样，也叫 top-$p$ 采样）**，阈值为 $p=0.9$。可以按每一步的词表分布理解：

1. 将候选 token 按预测概率从高到低排序。
2. 取累计概率达到阈值的最小前缀集合。
3. 在这个集合中重新归一化并采样一个 token，再继续下一步。

它不是每次固定取最高概率 token。作为对照，**beam search（束搜索）**保留多条高分候选前缀并逐步扩展，倾向寻找高分序列，但不保证找到全局最高概率句子。

论文实验发现：nucleus sampling 生成的描述虽然有更多被过滤器拒绝，却带来更好的下游结果。作者认为，保留下来的多样化描述可能提供更多新的语义信息。

> [!warning] 不是“噪声越多越好”
> 更准确的理解是：**生成侧增加多样性，过滤侧控制不可靠配对，两者配合改善训练数据。** Filter 的拒绝率不等于人工测量的真实错误率，过滤器也可能误删正确描述。
>
> 这是 CapFilt 制造训练数据时的解码策略；下游 captioning 评测使用 beam search。制造数据与最终评测不必采用同一种生成策略。

### 7.7 最后看实验：补写与过滤是否各自有用、一起更好？

![[_assets/images/BLIP-2201.12086-02-capfilt-ablation.png|900]]

读 Table 1 时，不要先盯着最大的数字。**先固定同一组数据规模与视觉骨干，再比较 captioner 和 filter 的开关。**

| 比较方式 | 在回答什么问题？ |
| --- | --- |
| 不用两者 vs. 只用 captioner | 补写描述本身有没有帮助？ |
| 不用两者 vs. 只用 filter | 清理原始描述本身有没有帮助？ |
| 单独使用 vs. 两者一起使用 | 增加监督与控制噪声是否互补？ |

作者报告：仅用 captioner 或仅用 filter 都有收益，两者结合进一步改善。论文还通过重复原始文本、对齐训练样本量的消融检查“只是训练更久”的解释，结果支持收益不只是延长训练带来的。

这些证据对应论文的特定数据、模型和评测设置，不代表任意生成器、过滤器和数据集都必然得到同样提升。参见 [BLIP 论文第 4 节与第 6 节](https://arxiv.org/abs/2201.12086)。

> [!summary] 第 6 节和第 7 节，一定要分清
> **第 6 节：固定当前训练数据，用三个任务共同更新模型参数。**
>
> **第 7 节：用已经学出的能力生成、过滤描述，改进训练数据，再训练一个新模型。**
>
> 前者回答“模型怎么学”，后者回答“下一轮用什么数据学”。CapFilt 的价值在于把生成与匹配能力用于数据改进，而不是再增加一个神秘的损失函数。

## 8. 从预训练到使用：对齐、理解和生成如何分工？

### 8.1 Batch 与候选数量：不能只照搬 CLIP 的大 batch 解释

CLIP 的基本对比候选来自当前 batch；BLIP 的 ITC 还使用动量特征队列。因此，要区分：

- 当前一起处理多少对图文。
- ITC 的分母中有多少个候选 key。
- ITM 实际抽取了多少个负配对。
- LM 中有多少个有效目标 token。

这四个数量不是同一个量。以单个对比计算中的 $B$ 和队列长度 $M$ 表示：

- ITC：每个 query 对应 $B+M$ 个候选 key。
- ITM：官方预训练实现构造 $3B$ 个配对分类样本。
- LM：对有效文本 token 求平均，padding 不算。

原论文报告的全局预训练 batch size 为：ViT-B 版本 $2{,}880$，ViT-L 版本 $2{,}400$；预训练 $20$ 个 epoch。其基础数据包含约 $14$ million 张图片，加入额外 LAION 数据后约为 $129$ million 张图片。

这些是论文设置，不要把单卡公式中的 $B$、全局 batch 与队列长度混为一谈；队列保存的是历史特征，也不等价于让所有历史样本同时参与在线反向传播。参见 [论文第 4.1 节](https://arxiv.org/abs/2201.12086)。

### 8.2 图文检索：ITC 先召回，ITM 再重排

图文检索可以分两步：

1. **快速召回**：用独立图像、文本向量的相似度，找出 top-$k$ 候选。
2. **精细重排**：对选出的候选进行图文融合编码，利用 ITM 分数重新排序。

这样不必对整个候选库逐对运行 cross-attention。原论文在 COCO 上使用 $k=256$，在 Flickr30K 上使用 $k=128$；检索微调使用 ITC + ITM。

![[_assets/images/BLIP-2201.12086-03-retrieval-results.png|900]]

上面的 Table 5 是经过对应检索数据集微调后的比较，而不是“所有模型在完全相同设置下直接零样本检索”的结果。它展示了这套预训练及下游使用方式的实际表现，但不能单凭一张表将收益全部归因于某一个 loss。

另外，图中的 `BLIP_CapFilt-L` 表示用更大的 captioner / filter 处理数据，再训练 ViT-B 学生；不要误读成学生模型一定也换成了 ViT-L。

### 8.3 Image captioning：启用图像条件解码器

Captioning 的输入只有图片和可选文本提示，不需要给出完整候选描述：

$$
I\rightarrow H^I
\rightarrow\operatorname{MED}_{\mathrm{dec}}
\rightarrow(t_1,t_2,\dots,t_L).
$$

下游 captioning 微调主要使用 LM loss。训练中的 ITC 与 ITM 并不会在每一步生成时都作为额外的分类程序执行；它们的影响已部分体现在预训练参数里。

还要区分两个场景：CapFilt 生成训练数据时，论文选择 nucleus sampling；下游 captioning 评测则使用 beam search。**制造训练数据的解码策略，不必与最终评测的解码策略相同。**

### 8.4 VQA：先融合图片与问题，再解码答案

VQA 不只是把 question 当作一条 caption 送去做相似度比较。

原论文在微调时重新组织模型：

$$
(I,Q)
\rightarrow\text{图像条件的问题编码器}
\rightarrow\text{图文融合表示}
\rightarrow\text{答案解码器}
\rightarrow A.
$$

训练时用真实答案构造 LM 目标。这个建模方式支持答案生成，但论文报告的 VQA 推理设置还使用解码器对 $3{,}128$ 个候选答案进行排序；不能把“采用生成式建模”直接等同于“所有实验都无约束地自由生成答案”。

这也说明，BLIP 是能灵活迁移到多个任务的预训练框架，不是一个无需任务适配、天然完成所有指令的通用聊天助手。参见 [论文第 5 节与附录](https://arxiv.org/abs/2201.12086)。

### 8.5 视频迁移与能力边界

原论文也测试了从图文任务向视频任务的迁移：均匀采样多帧，将帧特征拼接为序列。检索使用 $8$ 帧，视频问答使用 $16$ 帧。

但作者明确指出，这个简单做法**忽略时序信息**。因此，视频任务上的结果不能说明原始 BLIP 已经显式学会了复杂的动作顺序或长视频推理。

理解其能力时，还要保留几条边界：

- **对齐不等于完全理解**：ITC 与 ITM 都受数据和模型能力限制，可能误判细节。
- **能生成不等于不会幻觉**：LM 学到的是条件文本分布，不提供“每个生成词都可被画面验证”的保证。
- **过滤不等于绝对干净**：filter 的判断仍来自学习到的模型，可能漏掉错误或误删正确描述。
- **原始 BLIP 没有 Q-Former**：不要将其 cross-attention 与 BLIP-2 的桥接结构混为一谈。

这些边界不是否定 BLIP，而是提醒我们：**训练目标提供的是学习方向，不能把方向直接当成无限制的能力保证。**

## 9. 最后串起来：一个完整的心智模型

### 9.1 跟着同一张狗图片走一遍

1. **取得监督**：图片与描述配对，描述本身还提供逐 token 的训练目标。
2. **独立编码并对齐**：ViT 与文本 encoder 产生全局向量，ITC 结合动量特征、队列与软目标，让两种模态进入可比较的空间。
3. **联合编码并判断**：构造正配对与 hard negatives，文本通过 cross-attention 读取视觉 token，ITM 学习判断配对是否匹配。
4. **以图片为条件生成**：decoder 在不能偷看未来文本的条件下，利用图片与真实前缀预测下一个 token，学习描述画面。
5. **联合更新参数**：三个 loss 回传到各自使用的模块，共享参数累计多任务梯度；动量副本通过 EMA 更新。
6. **用模型改进数据**：独立微调 captioner 与 filter，生成新 caption，筛除原始与合成文本中的噪声，再用新数据训练新模型。
7. **按任务选用能力**：检索用独立编码与匹配重排，captioning 用条件解码，VQA 则组合问题编码与答案解码。

### 9.2 与 CLIP 对照，变化发生在哪里？

| 维度 | 原始 CLIP | 原始 BLIP |
| --- | --- | --- |
| 核心表征路径 | 图像、文本独立编码后比较 | 保留独立编码，并增加图文融合与条件解码 |
| 预训练目标 | 双向对比交叉熵 | ITC + ITM + LM |
| 图文交互 | 主要通过全局向量相似度形成训练联系 | ITM / LM 中文本直接 cross-attend 到视觉 token |
| 文本生成 | 原始模型不包含 caption 解码训练 | 明确训练图像条件自回归生成 |
| 对比监督实现 | 当前 batch 的双向配对分类 | 在线 / 动量分支、特征队列、硬软目标混合 |
| 数据改进 | 核心机制是从配对数据学习 | CapFilt 用生成与过滤改进后续预训练数据 |

BLIP 的模型训练可以记成：

$$
\boxed{
\text{ITC：在候选中找对应}
+\text{ITM：看细节判匹配}
+\text{LM：看图片续写文本}
}
$$

而完整框架还必须加上数据层面的：

$$
\boxed{
\text{训练模型}
\rightarrow\text{生成并过滤描述}
\rightarrow\text{构造更好的数据}
\rightarrow\text{训练新模型}
}
$$

所以，BLIP 不只是“CLIP 后面接一个 decoder”。它真正增加的是：**一套兼顾对齐、融合与生成的多任务架构，以及用这些能力反过来改进监督数据的流程。**

如果继续深入，最值得追问的三个问题是：软目标如何影响 false negatives，参数共享如何平衡理解与生成，以及 CapFilt 如何在描述多样性和事实准确性之间取得平衡。它们分别对应监督、模型和数据三个层面。
