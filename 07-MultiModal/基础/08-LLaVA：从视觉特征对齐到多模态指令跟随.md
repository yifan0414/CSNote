## 1. 从 BLIP-2 出发：能接入图片，为什么还要做视觉指令微调？

### 1.1 “看图写描述”和“按要求回答”不是同一件事

同一张狗在草地上跑的图片，用户可能提出不同要求：

| 指令 | 希望得到的回答形式 |
| --- | --- |
| “描述这张图片。” | 一段概括画面的 caption |
| “狗正在做什么？” | 聚焦动作的回答 |
| “只用一句话回答，背景是什么？” | 聚焦背景，并遵循长度约束 |
| “根据画面写一个小故事。” | 以视觉内容为条件的创作，而不只是列出物体 |

能生成一句 caption，说明模型可以把部分视觉内容表达成语言；但它不自动意味着模型会根据指令切换任务、关注点、回答长度和对话方式。

BLIP-2 已展示一定的提示跟随能力，并可复用 FlanT5 等模型原有的文本指令能力。LLaVA 则把**视觉指令跟随本身作为明确的数据与训练目标**。

> [!example] 设计的因果链
> 想让模型不仅描述画面，还能完成不同视觉指令 → 需要“图片 + 指令 + 回答”训练样本 → 用语言模型扩充已有图文标注 → 将视觉特征接入语言模型 → 联合微调接口与 LLM，让它们共同适应这些任务。
>
> 核心不只是“连接上了”，还包括“用什么样的回答监督它怎样使用这条连接”。

### 1.2 为什么结构反而可以更简单？先看设计，不急着下结论

LLaVA 保留冻结视觉塔，用简单投影层连接 LLM。它没有复制 BLIP-2 的 query 瓶颈，也没有先训练 ITC、ITM、ITG 三种 Q-Former 任务。

| 维度 | BLIP-2 的两阶段预训练 | 原始 LLaVA 的两阶段训练 |
| --- | --- | --- |
| 桥接模块 | Q-Former + 到 LLM 的投影 | 单层线性 projector |
| 视觉信息数量 | 通过固定数量的 query 输出传递 | 保留所选 patch 序列，逐 token 投影 |
| LLM 是否学习？ | 接入后保持冻结 | 第一阶段冻结，第二阶段更新 |
| 明确的训练重点 | 表征学习与冻结 LLM 的接口适配 | 特征对齐与视觉指令跟随 |

“LLaVA 让 LLM 也参与适应视觉输入”有助于理解这种设计，但**不能据此证明‘LLM 解冻，所以一定不需要 Q-Former’**。结构、数据、训练目标和可训练参数同时不同，不能把整体结果归因于单个变化。

### 1.3 名称里的 Instruction Tuning，具体是什么意思？

**Instruction tuning（指令微调）**：把任务写成自然语言要求，用示范回答做监督，让模型学会根据要求生成合适的输出。

“Visual”表示指令还依赖图像内容。它仍可以使用普通 next-token prediction 来训练，不一定需要新的损失函数，也不等同于 RLHF 或奖励模型训练。

原始 LLaVA 的贡献可以看作三件相互配合的事：**生成视觉指令数据、用简单架构完成两阶段训练、建立多模态指令评测。** 参见 [原论文](https://arxiv.org/abs/2304.08485v2)。

## 2. 监督信号：图片、指令与回答分别从哪里来？

> [!note] 先看训练样本，再看网络
> BLIP / BLIP-2 让你熟悉了“图文配对可以构造监督”。LLaVA 保留这一基础，再把监督组织成对话：**用户给图片和要求，助手给目标回答。**
>
> 两个阶段的数据不同，但都能写成条件文本生成任务。

### 2.1 第一阶段：把 image–caption pair 改写成单轮对话

假设原始数据是：

- 图片 $I$：狗在草地上跑。
- Caption $C$：`A dog is running on the grass.`

可以加入一条简短描述指令，改成：

| 角色 | 内容 |
| --- | --- |
| 用户输入 | 图片 + “简要描述这张图片。” |
| 助手目标 | 原来的 caption |

这里不需要重新为每张图片手写答案，**caption 本身就是目标**。论文从一组简短描述指令中随机选取表达方式，把筛选后的 CC3M 配对转成单轮对话。

### 2.2 第二阶段：描述指令太单一，需要更丰富的视觉任务

如果每次都问“描述图片”，模型没有充分练习对话、细节解释和推理型回答。

LLaVA 因此从 COCO 图像及其已有标注出发，构造三类数据：

| 数据类型 | 在练习什么？ | 论文报告的样本量 |
| --- | --- | --- |
| Conversation | 围绕对象、数量、动作、位置等进行多轮问答 | 约 $58{,}000$ |
| Detailed description | 根据要求给出更完整的描述 | 约 $23{,}000$ |
| Complex reasoning | 结合画面内容与背景知识进行解释、推理 | 约 $77{,}000$ |

合计约 $158{,}000$ 个指令样本，称为 LLaVA-Instruct-158K；不是 $158{,}000$ 张互不重复的图片，论文描述其涉及约 $80{,}000$ 张独立图片。Conversation 为多轮，其余两类为单轮。

### 2.3 文本版 GPT-4 没有看图，怎样生成视觉问答？

这是原论文最容易被误读的一点：**数据生成时使用的是 language-only GPT-4，不是把图片直接上传给多模态 GPT-4。**

作者把图片信息变成两类文字上下文：

| 给 GPT-4 什么？ | 能提供什么线索？ |
| --- | --- |
| Captions | 从不同角度描述画面内容 |
| 对象名称 + Bounding boxes 坐标 | 提供对象类别、位置和空间关系线索 |
| 人工设计的少量示例与指令 | 示范希望生成的问答形式、语气和边界 |

GPT-4 根据这些文本化的图像信息，生成对话、详细描述或推理问答。少量人工示例用于 in-context learning，不表示训练数据完全不依赖人类标注：COCO 的 captions、boxes 本身就是已有人工监督。

> [!example] 两条不同的数据流，不能画成一条
> **制造数据时**：图像已有的 captions / boxes → 文本版 GPT-4 → 指令与回答。
>
> **训练 LLaVA 时**：原始图片 → CLIP 视觉塔；指令 → LLM 文本输入；生成的回答 → 监督目标。
>
> GPT-4 没直接看图，不代表 LLaVA 训练时也只看 caption。LLaVA 确实接收图片特征。

### 2.4 生成的回答不等于无误的视觉事实

Captions 和 boxes 不一定包含图片所有细节，GPT-4 可能用语言先验补足不存在的信息。论文提示词尽量要求确定可回答的问题，但这不是准确性的保证。

这是一种**利用教师生成文本示范的数据构造方法**，不是在训练中直接匹配 GPT-4 的隐藏层或完整词表概率分布。普通 LLaVA 使用这些离线数据训练后，回答用户不必再调用 GPT-4。参见 [原论文第 3 节及附录 prompts](https://arxiv.org/abs/2304.08485v2)。

## 3. 网络架构：CLIP 视觉塔 + Projector + Vicuna

![[_assets/images/llava-2304.08485-01-architecture.png|900]]

原论文 Figure 1。图片经过视觉编码器得到特征，再通过投影层变成视觉输入；语言指令经过文本 embedding，与视觉表示一起交给语言模型生成回答。**图中没有 Q-Former，也没有单独的 ITM 分支。**

### 3.1 视觉塔提供 patch 特征，不是整套 CLIP 负责回答

对图片 $I$，记视觉特征为：

$$
Z_v=E_{\theta_v}(I)\in\mathbb{R}^{N_v\times d_v}.
$$

- $N_v$：选取的视觉 token 数量。
- $d_v$：CLIP 视觉隐特征维度。
- $\theta_v$：视觉编码器参数，在原始 LLaVA 两阶段训练中均冻结。

原论文使用 **CLIP ViT-L/14**。`L` 是 Large 配置，`/14` 指每个 patch 的大小为 $14\times14$ 像素，不是网络有 $14$ 层。

这里用的是视觉塔的 **grid / patch features**，不是 CLIP 最终用于图文余弦相似度的单个全局 embedding，也不把原 CLIP 的文本塔一起接入。论文比较了最后一层前后的视觉特征，ScienceQA 最佳配置采用最后一层之前的特征。

> [!info] 一个 shape 小例子：先把“数量”和“宽度”分开
> 对 $224\times224$ 图片，以 $14\times14$ 分块得到 $16\times16=256$ 个 patch。仅选 patch、不含 CLS 时，可写为 $Z_v\in\mathbb{R}^{256\times1{,}024}$。
>
> 这是帮助理解 patch 计数的输入配置示例，不是说所有 LLaVA 版本都固定 $256$ 个 token。图像分辨率、是否保留 CLS、裁剪策略都要按配置确认；也不要把后续版本常见的 $576$ 个 patch token 无条件套过来。

### 3.2 Projector：每个视觉 token 换一种坐标表示

LLM 的输入 embedding 维度记为 $d_\ell$。采用每行一个 token 的记法，论文的线性映射可以写成：

$$
H_v=Z_vW_P,
\qquad
W_P\in\mathbb{R}^{d_v\times d_\ell},
\qquad
H_v\in\mathbb{R}^{N_v\times d_\ell}.
$$

这里采用不显式写 bias 的论文式简化；若具体线性层实现含 bias，则对每个 token 加同一个偏置向量。本文矩阵方向按行向量统一，等价于原论文的列向量写法。

| 映射前后 | 发生了什么？ |
| --- | --- |
| $d_v\rightarrow d_\ell$ | 改变每个 token 的特征维度，满足 LLM 输入接口 |
| $N_v\rightarrow N_v$ | Token 数量不因这个逐位置线性层而减少 |
| 同一个 $W_P$ 处理所有位置 | 不是每个 patch 各自训练一套投影参数 |

**原始 projector 本身没有 query、没有 attention，也没有跨 token 的聚合操作。** 但每个输入 patch 特征已在 ViT 中与其他位置交互，所以不能误认为它只包含一小块原始像素。

### 3.3 维度相同，为什么还要训练？

随机矩阵也能把 $d_v$ 映射到 $d_\ell$，但 LLM 不会因此自动理解映射后的数字代表什么。

必须通过生成监督，让投影产生的视觉输入能够支持正确回答。**Shape 对齐只是接口条件，训练才让这个接口变得有用。**

投影后的 $H_v$ 是连续向量，不需要对应词表中的某个词，也不是先把图片解码为“dog、grass”，再送给 LLM。

### 3.4 文本走哪条路？Vicuna 又是什么？

用户指令 $Q$ 经过 Vicuna 对应 tokenizer 和文本 embedding，得到：

$$
H_q=\operatorname{Embed}_{\phi}(\operatorname{Tokenizer}(Q))
\in\mathbb{R}^{N_q\times d_\ell}.
$$

这里 $N_q$ 表示指令 token 数量，**不是 BLIP-2 的 learnable query 数量**；本篇没有那组 query embeddings。

Vicuna 是基于 LLaMA 做过对话指令微调的 decoder-only 语言模型。LLaVA 复用其已有语言和对话能力，而不是让一个随机语言模型仅靠图文数据从头学会说话。

视觉向量与文本向量在对话模板规定的位置组成同一输入序列。以视觉在问题之前的布局简写：

$$
X=\operatorname{Concat}_{\mathrm{seq}}(H_v,H_q,\text{已有回答的 embeddings}).
$$

真实序列还包括系统提示、角色与分隔标记；原论文第一轮会在“问题 + 图片”和“图片 + 问题”两种组织中随机选择，后续轮次继续追加对话。不要把简图中的“全部视觉永远在所有文本之前”当成唯一模板。

## 4. 图文交互：没有 Q-Former，不等于没有融合

> [!note] 先抓住主线
> Projector 只负责逐 token 映射 → 视觉与文本进入同一 LLM 序列 → 回答位置通过 self-attention 读取前面的图像、指令和历史 → 逐层形成支持回答的隐状态。
>
> 因此，融合主要发生在 LLM 内，而不是 projector 中。

### 4.1 为什么叫 self-attention，而不是另加 cross-attention？

对 LLM 某层的联合序列隐状态 $X$，普通 attention 可写成：

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V,
$$

$$
\operatorname{Attention}(X)
=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V.
$$

$M$ 是因果与有效位置掩码。Q、K、V 来自同一条联合序列，所以结构上是 self-attention；序列里同时有视觉和文本表示，因此功能上能够发生跨模态交互。

**“跨模态交互”是信息来自不同模态，“cross-attention 层”是特定的网络结构，两者不是同义词。** 原始 LLaVA 没有新增 Q-Former 式图像 cross-attention，并不妨碍 LLM 的文本位置读取视觉位置。

### 4.2 因果方向不能忽略：不是图文任意双向读取

假设本次布局是“视觉前缀 → 问题 → 回答前缀”：

| 位置 | 通过 LLM 的因果 attention 能读取什么？ |
| --- | --- |
| 视觉位置 | 序列中它之前及当前位置的输入，不能看之后的问题 |
| 问题位置 | 前面的视觉位置与此前文本 |
| 回答位置 | 前面的视觉、问题、历史对话和已有回答 |

在进入 LLM 之前，ViT 内部已经做过视觉 self-attention；“LLM 中有因果限制”不等于“视觉塔只看过图像的一部分”。

> [!warning] 换问题，不要默认前置视觉表示也跟着变
> 同一张图片经过冻结 CLIP 与普通 projector，得到的 $Z_v$、$H_v$ 不依赖具体问题。问题影响的是 LLM 后续如何利用这些特征。
>
> 对纯视觉前缀在前的 causal 布局，前缀位置的 LLM 隐状态也不能读取后来才出现的问题。因此不能笼统说“进入 LLM 后所有视觉 token 都自动变成 question-conditioned”。若模板让问题位于图片之前，则需按实际位置重新分析可见性。

### 4.3 读图不等于每个 attention head 都是定位器

回答“狗在做什么”时，模型可以通过联合 attention 利用有助于动作判断的视觉信息；但仅凭架构，不能保证某个 head 就精准定位狗，或某个 patch 永远只表示一个对象。

这一节解释的是模型**具备怎样的信息读取路径**，不是为准确性、空间理解或可解释性作保证。

## 5. 第一阶段：用 caption 生成监督训练视觉接口

> [!example] 为什么先只训练 projector？
> 视觉塔已有特征、LLM 已有语言能力，但两者之间的投影尚未适配 → 先固定两端 → 让 projector 产生能支持 caption 生成的输入 → 再进行更丰富的视觉指令微调。
>
> 可以把它理解成先校准接口；不能把“直接联合训练必然不稳定”当成论文已经证明的普遍结论。

### 5.1 数据：筛选后的 CC3M，不是第二阶段的 GPT-4 问答集

原论文从 CC3M 中筛出约 $595{,}000$ 对图文，兼顾概念覆盖与训练规模。其附录按 caption 的名词短语频率筛选，减少冗余；不是简单随机拿同样数量的数据。

每个样本变成：**图片 + 简短描述请求 → 原始 caption**。此时大部分指令只是表达“请描述图片”的不同方式。

### 5.2 参数：视觉塔冻结，Vicuna 也冻结

| 模块 | 第一阶段是否更新？ |
| --- | --- |
| CLIP 视觉编码器 | 否 |
| Projector | 是 |
| Vicuna | 否 |

记 projector 参数为 $\theta_P$，LLM 参数为 $\phi$，caption 为 $C=(c_1,\dots,c_L)$，描述指令为 $Q_{\mathrm{desc}}$。忽略平均系数：

$$
\mathcal{L}_{\mathrm{align}}
=-\sum_{t=1}^{L}\operatorname{log}
 p_{\phi}\left(c_t\mid H_v(I;\theta_P),Q_{\mathrm{desc}},c_{<t}\right).
$$

$\phi$ 固定，$H_v$ 随可训练的 projector 改变，优化器据此更新 $\theta_P$。

### 5.3 这里的“对齐”，为什么不是 ITC？

| | CLIP / BLIP-2 的 ITC | LLaVA 第一阶段 |
| --- | --- | --- |
| 要预测什么？ | 候选集合中的配对对象 | 真实 caption 的下一 token |
| 是否构造候选图文相似度矩阵？ | 是 | 不需要 |
| 是否需要 batch 内错配作对比负例？ | 是 | 该生成目标不需要 |
| 训练信号 | 配对分类交叉熵 | 词表生成交叉熵 |

> [!tip] 对齐是目的，不是固定的 loss 名称
> LLaVA 用“生成正确描述”来约束视觉接口：投影后的特征若有用，冻结 LLM 就更容易预测真实 caption。**它不是让视觉 token 逐个拟合某个词向量，也不要求一个 patch 对应一个词。**
>
> 第一阶段的作用更接近 BLIP-2 接入冻结 LLM 的生成接口学习，而不是 BLIP-2 尚未接入 LLM 的 ITC / ITM / ITG 阶段。

参见 [原论文第 4 节](https://arxiv.org/abs/2304.08485v2)。

## 6. 第二阶段：视觉塔仍冻结，让 projector 与 LLM 一起学会回答

> [!note] 这里真正改变了 LLM 的权重
> 第一阶段接口已初步适配 → 换成更丰富的视觉指令示范 → 解冻 LLM → projector 与 LLM 共同学习如何按用户要求使用视觉信息。
>
> 两个阶段不只是训练时间前后不同，**训练数据与可更新模块都发生了变化**。

### 6.1 多模态聊天：目标不再总是固定的 caption

同一张狗图片可以配不同问题和回答。记单轮样本为 $(I,Q,A)$，学习的是：

$$
p(A\mid I,Q),
$$

而不是只学 $p(C\mid I)$。

例如：

| 用户指令 | 助手目标示例 |
| --- | --- |
| “狗正在做什么？” | “它正在草地上跑。” |
| “背景是什么？” | “背景主要是草地。” |
| “用一句话概括。” | 简短回答，而不是无条件展开长段描述 |

这些是教学例子，不是论文报告的特定训练条目。关键在于：**图片相同，指令不同，合适的目标回答也不同。**

### 6.2 参数更新：不要把 end-to-end 理解成所有模块都训练

| 模块 | 第一阶段 | 第二阶段 |
| --- | --- | --- |
| CLIP 视觉塔 | 冻结 | 仍冻结 |
| Projector | 更新 | 继续更新 |
| Vicuna | 冻结 | 更新 |

论文把第二阶段称为 end-to-end fine-tuning，但明确保持视觉编码器冻结。这里表示生成损失联合训练接口与语言模型，**不是 CLIP、projector、LLM 所有参数从头到尾一起更新**。

这也是与 BLIP-2 两阶段预训练的重要差异：后者外部 LLM 保持冻结，LLaVA 第二阶段允许语言模型本身适应视觉指令。

### 6.3 对话怎样展开：所有回答都可以成为目标

设一张图关联多轮对话 $(Q^1,A^1),\dots,(Q^R,A^R)$。输入按系统提示、用户指令、助手回答依次串联，第一轮提供图片，后续轮次追加文本。

训练预测第 $r$ 轮回答时，可以使用前面的图像与对话历史，但不能读取未来回答或后面的提问。

例如第二轮“那它在哪里？”可以利用前一轮关于狗的问答来消解指代。这不是分别对每轮独立计算 image–text similarity，而是在同一语言上下文里继续生成。

### 6.4 ScienceQA 是另一种第二阶段使用场景

原论文还研究在 ScienceQA 上微调：输入是问题、选项以及文字 / 图片上下文，输出是推理解释与答案。

**多模态聊天微调和 ScienceQA 微调是论文考虑的两种使用场景，不能默认必须先完整训好聊天模型，再继续做 ScienceQA。** ScienceQA 的结果也不能当成原始聊天 checkpoint 未经任务微调的零样本成绩。

## 7. 回答 loss：读入整段对话，但不对所有输入位置都计分

> [!note] 这一节区分两件经常混在一起的事
> **Attention mask**决定模型能读哪些位置；**loss mask**决定哪些目标位置参与损失。
>
> 用户问题要被模型读到，但通常不是要求助手去生成的目标；视觉向量也作为条件输入，而不是词表中的正确答案。

### 7.1 Teacher forcing：训练看真实前缀，推理接自己的输出

假设助手回答是 `The dog is running.`，训练可以构造：

| 已有输入条件 | 下一目标 |
| --- | --- |
| 图片 + 问题 + 助手起始提示 | `The` |
| 图片 + 问题 + `The` | `dog` |
| 图片 + 问题 + `The dog` | `is` |
| 图片 + 问题 + `The dog is` | `running` |

这里按词演示，实际按 tokenizer 的 token。训练时使用真实答案前缀，通过 causal mask 可以并行算各位置预测；推理时没有真实答案，只能用刚生成的 token 继续。

### 7.2 哪些位置有 label，哪些位置只作条件？

| 序列内容 | 主要角色 |
| --- | --- |
| 视觉向量 | 条件输入，没有要预测的离散视觉词表 ID |
| 用户问题 / 指令 | 条件输入，不作为助手回答正文训练 |
| 真实助手回答 | 下一 token 监督目标 |
| 停止标记 | 教模型何时结束；具体监督位置随模板定义 |
| Padding | 对齐长度，不参与有效目标损失 |

原论文的训练格式要求预测助手回答以及停止位置，采用 Vicuna-v0 的模板并以 `###` 表示 `<STOP>`。不要把这个历史模板当成所有后来版本通用的结束 token。

> [!warning] “不计 loss”不等于“不可见”，也不等于“不会收到梯度”
> 用户指令和视觉前缀即使不直接作为目标，也会影响回答预测。回答损失可以经 attention 回传到可训练的输入映射和语言模型参数。
>
> Loss mask 不是把这些输入从上下文里删掉；它只是决定哪些预测位置直接计分。

### 7.3 最后把它写成统一的生成交叉熵

记所有被监督的回答 / 停止目标位置集合为 $\Omega$，目标 token 为 $y_t$，此前完整可见上下文为 $X_{<t}$。用对有效目标取平均的教学写法：

$$
\boxed{
\mathcal{L}_{\mathrm{gen}}
=-\frac{1}{|\Omega|}\sum_{t\in\Omega}
\operatorname{log}p_{\theta_P,\phi}(y_t\mid X_{<t})
}
$$

$X_{<t}$ 包含先前的视觉输入、指令、对话与真实回答前缀；不包含未来文本。具体 batch 归约与分隔符处理要看实现和模板。

对于单轮问题，也可概括为：

$$
p(A\mid I,Q)=\prod_{t=1}^{L_A}
 p(a_t\mid I,Q,a_{<t}).
$$

两个阶段使用相同类型的生成目标，主要区别是：**第一阶段答案是 caption、只更新 projector；第二阶段答案是指令响应、同时更新 LLM。** 参见 [原论文的训练序列与自回归目标](https://arxiv.org/abs/2304.08485v2)。

## 8. 梯度与参数更新：简单 projector 怎样被训练出来？

### 8.1 冻结 LLM，也能把梯度传回 projector

第一阶段计算路径是：

$$
I\xrightarrow{E_{\theta_v}}Z_v
\xrightarrow{P_{\theta_P}}H_v
\xrightarrow{\operatorname{LLM}_{\phi}}p
\rightarrow\mathcal{L}.
$$

即使 $\phi$ 固定，损失仍随 LLM 输入 $H_v$ 改变，因此：

$$
\frac{\partial\mathcal{L}}{\partial\theta_P}
=\frac{\partial\mathcal{L}}{\partial H_v}
\frac{\partial H_v}{\partial\theta_P}.
$$

其中对 $H_v$ 的梯度经过 LLM 内部计算得到。**冻结 LLM 参数，不等于把整个训练前向放到 `no_grad` 里**；否则会切断接口学习所需的输入梯度。

这与 BLIP-2 冻结 LLM、训练桥接模块的梯度逻辑相通，只是这里的桥更简单。

### 8.2 第二阶段：接口和“读取接口的人”一起调整

第二阶段除了上面的 projector 梯度，还计算并使用：

$$
\frac{\partial\mathcal{L}}{\partial\phi}.
$$

可以理解成：

- Projector 调整“提供怎样的视觉输入”。
- LLM 调整“怎样根据图像、问题和历史生成回答”。
- CLIP 视觉骨干仍保持固定，不随本阶段回答损失更新。

这里应说“视觉骨干参数不由优化器更新”，而不是说损失对它们的数学导数必然为零。实现可以通过冻结参数及不构建不必要的视觉反向图节省训练资源。

### 8.3 逐 token 投影，为什么也能汇总整段回答的监督？

对简化线性层 $H_v=Z_vW_P$，记 $G=\partial\mathcal{L}/\partial H_v$，则：

$$
\frac{\partial\mathcal{L}}{\partial W_P}=Z_v^\top G.
$$

所有视觉位置共享同一个投影矩阵，所以它们对参数的梯度会汇总。$G$ 已经包含经过 LLM 传播而来的、所有受监督回答位置的影响。

Projector 不需要自己拥有 attention，才能从完整回答中学习；**复杂的条件依赖由后面的 LLM 建立，梯度再传回这个简单映射。**

### 8.4 损失的直接纠偏，仍是“预测减目标”

对于词表 softmax + 硬目标交叉熵，忽略平均系数：

$$
\frac{\partial\ell_t}{\partial u_{t,v}}
=p_{t,v}-y_{t,v}.
$$

正确 token 获得的概率太低时，其 logit 有被提高的直接倾向。实际修改的是共享参数，不保证每一步每个回答 token 的分数都按单项分析改变。

> [!success] 一次更新的心智模型
> **图片提特征 → projector 映射 → LLM 结合指令预测回答 → 只在目标位置计算生成 loss → 梯度穿过 LLM 回到接口。**
>
> 第一阶段只更新接口；第二阶段接口与 LLM 一起更新。全过程都不要求先计算 ITC 或 ITM。

## 9. 与 BLIP-2 对照：改变的是分工，而不是简单的“新模型替代旧模型”

### 9.1 最值得对照的是 token 数量、交互位置与更新策略

| 对比维度 | BLIP-2 基础生成路径 | 原始 LLaVA |
| --- | --- | --- |
| 视觉塔 | 冻结预训练 ViT | 冻结 CLIP ViT-L/14 |
| 桥接结构 | Q-Former + 投影 | 单层线性 projector |
| Token 数量变化 | 输出固定数量 queries，论文为 $32$ | 逐 token 投影，不因 projector 减少数量 |
| LLM 前是否有可学习视觉读取？ | 有，query cross-attention | 没有对应的 query / resampler 模块 |
| 图文生成交互 | Query 提供视觉提示，LLM 使用提示 | Patch 特征直接投影，LLM 使用更长视觉输入 |
| LLM 在后期是否更新？ | 两阶段预训练中冻结 | 第二阶段更新 |
| 显式 ITC / ITM 训练 | 第一阶段有 | 原始 LLaVA 两阶段没有 |
| 主要输出接口 | 可有第一阶段匹配 / 表示，也可生成 | 面向指令的文本回答 |

### 9.2 为什么不能说“冻结 LLM 必须配复杂桥”？

LLaVA 自己的第一阶段就证明了设计上可以使用“冻结 LLM + 简单线性 projector”做生成接口训练。Q-Former 是 BLIP-2 选择的有效方式，但不是冻结 LLM 的逻辑必需条件。

更谨慎的总结是：**BLIP-2 显式训练可选择、可压缩的视觉接口；LLaVA 以简单接口快速开展数据实验，再让 LLM 参与适应视觉指令。** 原论文也把更复杂连接结构留作可探索方向，并未证明简单结构在所有任务都优于 Q-Former。

### 9.3 少了 Q-Former，不代表整条推理链一定更便宜

简单 projector 减少了桥接模块的计算，但如果向 LLM 传入更多视觉 token，后面的序列计算与缓存开销可能增加。

若视觉 token 数为 $N_v$、文本序列长度为 $N_t$，普通密集 self-attention 的分数计算规模与 $(N_v+N_t)^2$ 相关。这里仅用于解释序列长度影响，不能把它直接当成整个系统的运行时间或实际峰值显存公式。

**桥接成本、LLM 输入长度、模型大小和实现优化要一起看。** 不能只比较 Q-Former 与线性层的参数量，就断言某个系统总是更快。

## 10. 版本边界：原始 LLaVA、LLaVA-1.5 与后续扩展不要混写

| 内容 | 本文对应的原始 LLaVA | 后续版本需要另行确认 |
| --- | --- | --- |
| Projector | 单层线性映射 | LLaVA-1.5 使用两层 MLP |
| 视觉输入 | CLIP ViT-L/14，按配置选择 grid 特征 | 分辨率、裁剪与 token 数随版本变化 |
| 训练数据 | 论文中的 CC-595K 与 Instruct-158K 等设置 | 后续扩充数据混合，不沿用这些数量作为统一定义 |
| 图像 / 视频能力 | 原论文主要研究单图指令与 ScienceQA | 多图、视频与高分辨率策略属于相应后续工作 |

LLaVA-1.5 的 MLP 可概括为逐 token 的线性层、GELU、线性层，仍不等于引入 query 压缩。关于后续改进只用来辨别版本，详见 [LLaVA-1.5 原论文](https://arxiv.org/abs/2310.03744)及[官方 projector 实现](https://github.com/haotian-liu/LLaVA/blob/main/llava/model/multimodal_projector/builder.py)。

> [!warning] 读复现代码时，也要确认 checkpoint 与模板
> 不能把今天仓库 `main` 分支支持的所有结构、LoRA 选项、数据和模板都当成原始论文实验。论文、训练脚本和 checkpoint 配置需要配套阅读。
>
> 同样，$1{,}024\rightarrow4{,}096$ 这类维度示例依赖具体 LLM 配置，不是所有 Vicuna 规模都相同；本篇因此优先使用 $d_v\rightarrow d_\ell$ 的统一记法。

## 11. 从模型到下游：给用户的是回答，给研究者的不一定是匹配分数

### 11.1 推理：图像、问题、历史共同决定答案

输入图片与用户问题，计算视觉特征及投影，按对话模板进入 LLM，自回归生成回答，直到停止条件满足。

训练使用真实答案前缀；推理使用自己生成的前缀，早期错误可能影响后面内容。普通推理不需要 GPT-4 在线出题或评分，也不需要重新运行两阶段训练。

### 11.2 为什么不直接把 LLaVA 当成 CLIP 式检索编码器？

CLIP 明确训练独立图文向量的可比性，BLIP-2 第一阶段还明确训练 ITM 分类头。LLaVA 则主要训练给定图片和指令后的文本生成。

| 想拿什么？ | 原始 LLaVA 是否直接提供对应的训练接口？ |
| --- | --- |
| 描述、问答、解释文本 | 是，这是主要接口 |
| 视觉塔的 patch 特征 | 可以提取，是其组成模块的输出 |
| Projector 后的视觉 token | 可以提取，但不自动等于已校准的检索 embedding |
| 显式 matched / unmatched 的 ITM head | 没有原始 BLIP-2 那套专门训练的 ITM 接口 |
| 一次独立编码后可直接比较的图文检索分数 | 不是这套生成训练直接承诺的接口 |

可以设计基于回答概率或“是否相关”提示的 scorer，但那是额外使用方案，需要评估成本、提示敏感性与校准，不能把它自动当成 ITM 分数。

### 11.3 与视频选帧的联系：先区分 scorer 和回答模型

在视频研究中，可以让 CLIP / SigLIP / BLIP-2 ITM 承担候选帧相关性估计，再让支持相应输入的多模态模型回答。这是不同模块分工，不是单纯按模型新旧排序。

但原始 LLaVA 的单图实验不证明它已经有显式时序建模。把多帧特征简单拼起来还会增加 token 成本，帧顺序、时间位置、多图训练与实际接口都需要单独设计和验证。

> [!tip] 参考讨论中的判断应改成可验证的问题
> “融合 scorer 一定比 CLIP 相似度好”“LLaVA 一定不适合表征提取”都过于绝对。应问：**当前任务需要什么输出？它接受过什么监督？表示是否依赖问题？每个候选要付出多少计算？**

## 12. 实验证据：先看评测方式，再解释分数

### 12.1 训练规模：不是从零训练 CLIP 和 Vicuna

论文报告用 $8$ 张 A100：

- 第一阶段：CC-595K，$1$ 个 epoch，学习率 $2\times10^{-3}$，batch size 为 $128$。
- 聊天第二阶段：Instruct-158K，$3$ 个 epoch，学习率 $2\times10^{-5}$，batch size 为 $32$。
- 附录报告相应预训练在 $4$ 小时内完成，聊天微调在 $10$ 小时内完成；这些是论文设置，不是任意机器上的时间承诺。

这些训练成本没有包括从头获得 CLIP、LLaMA、Vicuna 的成本；也不能把较小的新增图文数据规模解释成模型此前没有见过大规模视觉或语言数据。

### 12.2 COCO 指令消融：$85.1\%$ 不是普通分类准确率

![[_assets/images/llava-2304.08485-02-instruction-data-ablation.png|900]]

LLaVA-Bench (COCO) 使用 $30$ 张验证图片和 $90$ 个问题，覆盖对话、详细描述、复杂推理。候选模型接收图片与问题；文本版 GPT-4 则根据图像的文字化标注产生参考答案，并作为 judge 对回答质量评分。

Table 4 的结果是**相对 GPT-4 参考回答的评分**。完整指令数据的总体相对分数为 $85.1\%$，只用 conversation 为 $73.8\%$，不做 instruction tuning 为 $21.5\%$。作者据此支持视觉指令微调及数据多样性的作用。

> [!warning] 不要读成“达到了 GPT-4 的整体能力的 $85.1\%$”
> 这是小型特定评测、特定参考输入和 GPT-4 评分协议下的相对值，不是通用能力百分比，也不是直接与能看图的 GPT-4 在完全相同输入下比较。

### 12.3 In-the-Wild：更难场景上的指令跟随比较

![[_assets/images/llava-2304.08485-03-in-the-wild-results.png|900]]

这一集合包含 $24$ 张图片、$60$ 个问题，覆盖不同场景、梗图、绘画和草图等，并提供详细人工描述辅助评价。

Table 5 中 LLaVA 的总体相对分数为 $67.3\pm2.0$，BLIP-2 为 $38.1\pm1.0$。前三行反映多次生成运行；带 dagger 的行固定 LLaVA 生成结果，多次调用 GPT-4 评估，检验 judge 的一致性。

它支持论文设置下视觉指令微调对开放式回答的帮助，**不是证明 LLaVA 的视觉表征、检索、定位等所有能力都超过 BLIP-2，也不能单独证明线性层比 Q-Former 更好**。

### 12.4 ScienceQA：单模型成绩与 GPT-4 集成成绩分开看

![[_assets/images/llava-2304.08485-04-scienceqa-results.png|900]]

ScienceQA 是有监督多项选择任务，部分问题有图片上下文，部分依赖文字或没有额外上下文。原论文训练模型生成解释与答案，最佳配置的单模型平均准确率为 $90.92\%$。

$92.53\%$ 对应 **LLaVA + 文本版 GPT-4 judge 的集成**：两者给出不同答案时，再请 GPT-4 结合问题与两份结果作决定。不能把它归给独立 LLaVA 聊天模型，也不能当成零样本分数。

表中的 GPT-4 complement 是另一种组合策略：GPT-4 未能提供答案时采用 LLaVA 的输出。它与冲突时重新判断的 judge 方案不同。

### 12.5 设计消融：第一阶段有用，但不是所有训练顺序都已被证明最优

![[_assets/images/llava-2304.08485-05-design-ablation.png|900]]

读 Table 8 时，先固定这是 ScienceQA 任务上的比较：

- 论文中使用最后一层之前的视觉特征优于最后一层输出；作者对局部信息的解释属于假设，不是每层功能的普遍定理。
- 跳过第一阶段、直接进行 ScienceQA 训练，准确率降至 $85.81\%$，支持先做接口对齐在该设置下的价值。
- 表中 “Training from scratch” 指跳过 LLaVA 的第一阶段，**不是把 CLIP 和 LLM 都随机初始化从零训练**。
- 论文还比较模型规模与先解释 / 先答案的生成顺序；作者认为 reasoning-first 有助于收敛，但不要扩展成“写出推理过程就一定提升最终准确率”。

## 13. 能力边界：会按要求说话，不等于每句话都有视觉证据

### 13.1 论文明确观察到的局限

- **细粒度语义组合会出错**：论文给出冰箱中有草莓、也有酸奶，模型却误认为有“草莓味酸奶”的案例。识别对象不等于正确理解属性归属。
- **高分辨率细节与知识仍有困难**：品牌、小字、具体食物等问题可能受视觉分辨率与知识覆盖限制。
- **会继承基础模型的幻觉和偏见**：CLIP 与语言模型已有的问题可能传递到整个系统。
- **评估仍不完善**：GPT-4 judge 在论文实验中的一致性不保证它在所有场景都准确、公平或全面。

### 13.2 根据方法需要保留的理解边界

- **合成指令也可能有噪声**：教师没直接看到图片，文本标注不完整时可能补出错误信息。
- **更多 token 不保证无损**：即使 projector 不压缩 token，原图预处理与视觉编码仍可能丢失细节。
- **合理的长回答不等于正确推理**：生成目标优化示范答案概率，不直接证明中间解释就是模型真实、可靠的求解过程。
- **单图能力不等于视频时序能力**：图片预训练和单图指令微调不直接提供长视频理解保证。
- **原论文不是完整安全对齐方案**：有监督指令微调、示例过滤和外部防护都不能保证所有不当输出被消除。

> [!warning] 把“架构允许什么”和“实验证明什么”分开
> LLM 可以读取视觉 token，不等于它每次都充分读取；指令数据包含推理，不等于推理永远正确；相对评分提高，也不等于所有下游接口同步改善。

## 14. 最后串起来：跟着同一张图片走完 LLaVA

### 14.1 两个阶段，一条生成路径

1. **先有现成能力**：CLIP 会提取视觉特征，Vicuna 已有语言与对话能力。
2. **准备监督**：第一阶段用图片与 caption，第二阶段用图片、指令与回答。
3. **提取视觉序列**：冻结 CLIP 输出 patch 特征，不先压成 Q-Former queries。
4. **映射输入空间**：线性 projector 把每个视觉向量变成 LLM 输入维度，数量不因此减少。
5. **第一阶段校准接口**：冻结 LLM，用 caption 生成 loss 训练 projector。
6. **第二阶段学习任务**：解冻 LLM，保持视觉塔冻结，用指令回答联合训练 projector 与 LLM。
7. **推理按要求生成**：图片、问题与历史按模板输入，模型逐 token 输出回答，不必在线调用 GPT-4。
8. **按任务判断是否合适**：文本回答是主要接口；要做检索、帧评分或表征提取，需要另行确认使用路径和评估方式。

### 14.2 从 CLIP 到 LLaVA，问题发生了什么变化？

| 模型 | 最适合用来建立的核心认识 |
| --- | --- |
| CLIP | 图像与文本独立编码，训练可比较的全局表示 |
| BLIP | 同一图文数据同时支持对齐、融合匹配与条件生成 |
| BLIP-2 | 用 queries 提取视觉信息，并适配冻结 LLM |
| LLaVA | 用简单视觉接口和指令数据，让 LLM 参与学习如何根据图片与要求回答 |

> [!success] 最后记住的不是“Q-Former 被线性层淘汰”
> **BLIP-2：训练更明确的视觉读取与压缩接口，复用冻结 LLM。**
>
> **LLaVA：先训练简单视觉接口，再用视觉指令联合微调接口与 LLM。**
>
> 架构、数据、目标和参数更新共同决定能力；不能只盯着中间连接层的复杂度。

### 14.3 继续深入时，值得追问的问题

1. **固定数据与训练策略，单独换 projector 能带来多少收益？** 这样才能区分结构和数据的贡献。
2. **更多 patch token 与少量 query tokens 怎样权衡？** 同时测细节保留、LLM 开销和任务准确率。
3. **如何识别模型只依赖语言先验的回答？** 比较替换图片、打乱视觉输入、无图输入等受控设置，而不是只看文字流畅度。
4. **做视频选帧时，问题条件化应该发生在哪里？** 独立视觉评分、融合匹配与最终 LLM 回答是不同阶段，不必由一个模型包办。

这些是后续研究问题，不是原论文已经给出的结论。
