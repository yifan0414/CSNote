# CS224N 17：分词与多语言

> [!abstract] 本节定位
> 比较词、字符或字节和子词 tokenization，演算 BPE，分析分词对拼写、跨语言迁移与公平性的影响。

## 学习目标

- [ ] 手工执行若干轮 BPE merge
- [ ] 用 fertility 解释不同语言的 token 成本
- [ ] 分析跨语言迁移的数据、字形和语系条件

## 知识笔记

> [!info] 课件范围
> 对应 Tokenization and Multilinguality PPT 第 3–75 页：词/字符/字节/子词切分、BPE 完整演算、SentencePiece、拼写与 glitch token、多语言预训练、cross-lingual transfer、curse of multilinguality 和分词公平性。

## 1. 什么是“词”

自然语言中的单位并不唯一：

- 字符；
- 字节；
- 语素；
- 词；
- 多词表达；
- 短语。

例如英语缩写、屈折变化和专名会让“按空格数词”与语言学词数不同。

语言模型真正看到的是 tokenizer 定义的 token，而不是人类预先认可的词。

## 2. Tokenizer 的接口

编码：

$$
\operatorname{encode}:
\text{text}\to[t_1,\ldots,t_N].
$$

解码：

$$
\operatorname{decode}:
[t_1,\ldots,t_N]\to\text{text}.
$$

词表：

$$
V=\{v_1,\ldots,v_{|V|}\}.
$$

Tokenizer 决定：

- 序列长度；
- embedding/output 层大小；
- 模型可直接操作的最小单位；
- 推理成本和 API 计费；
- 不同语言的表示效率。

## 3. Word Tokenization

以空格和标点预切分，再将词映射到词表。

优点：

- 序列短；
- token 对人类可解释；
- 词是常见语义单位。

缺点：

- 未登录词；
- 词形变化产生大词表；
- 拼写错误；
- 没有空格的语言；
- 专名和新词不断出现。

UNK 会把大量不同未知词压成同一 id，信息不可恢复。

## 4. Character/Byte Tokenization

### Character

词表覆盖 Unicode 字符。没有词级 OOV，但：

- 词表仍受字符集合影响；
- 序列显著变长；
- 高层语义需要模型自己组合。

### Byte

UTF-8 字节只有 256 个基础值，可表示任意文本。

优点：

- 真正无 OOV；
- 可直接观察字符组成；
- 对新语言和噪声更稳健。

缺点：

- 序列更长；
- 一个 Unicode 字符可能对应多个 byte；
- 标准 attention 成本升高。

## 5. 子词的折中

常见词保留为一个 token，罕见词分成更小单位：

$$
\text{picking}
\to
\text{pick}+\text{ing}.
$$

目标：

- 保持可逆；
- 消除词级 OOV；
- 共享词形；
- 控制词表与序列长度。

## 6. Byte Pair Encoding 训练

从基础符号序列开始，反复合并最高频相邻 pair。

伪代码：

```text
vocab = initial symbols
repeat:
    count every adjacent pair
    pair = argmax count
    merge pair in all words
    append pair to merge list
```

训练产物不仅是词表，还包括有顺序的 merge rules。

## 7. BPE 演算

假设初始词被表示为字符，并显式保留词首或空格符号：

```text
_ p i c k
_ p i e r
_ p i c k i n g
```

若最高频 pair 是 `_ + p`：

```text
_p i c k
_p i e r
_p i c k i n g
```

下一轮可能合并 `c + k -> ck`，再合并 `_p + i -> _pi`。

最终规则类似：

```text
1. _ + p -> _p
2. c + k -> ck
3. e + r -> er
4. _p + e -> _pe
5. _p + i -> _pi
6. _pi + ck -> _pick
```

每轮频数必须在上一次合并后的语料上重新统计。

## 8. BPE 推理

对新文本：

1. 转成基础字符或字节；
2. 按训练得到的规则顺序应用；
3. 不能根据当前词临时选择新的合并。

例如 `_pier`：

```text
_ p i e r
-> _p i e r
-> _p i er
-> _pi er
```

即使某个 pair 在测试词里看起来合理，没有训练规则也不能合并。

## 9. BPE 的目标不是形态学

BPE 优化频率压缩，不显式知道 morpheme。

可能得到语言学合理单位：

$$
\text{walk}+\text{ing}.
$$

也可能得到只因高频而存在、没有独立语义的片段。

因此不能把 subword token 自动解释为语素。

## 10. Pretokenization 与 SentencePiece

许多 tokenizer 先按空格分词，再在每个“词”内部 BPE。这会限制跨空格合并。

问题：

- 中文、日文、泰文不依赖空格分词；
- 多词表达可能应整体处理；
- 空格本身包含信息。

SentencePiece 是 tokenizer 工具库，不是单一算法。它可实现：

- BPE；
- Unigram LM；
- 将空格视为普通符号；
- 从原始文本直接训练。

## 11. Unigram Language Model Tokenization

从一个较大候选词表开始，为 token 分配概率。

分词概率：

$$
P(t_1,\ldots,t_k)
=
\prod_iP(t_i).
$$

对一个字符串，使用动态规划寻找最高概率切分，并逐步删除贡献小的 token，直到目标词表大小。

BPE 是从小词表逐步合并；Unigram LM 是从大词表逐步剪枝。

## 12. 拼写与字符任务

模型看到 subword，不一定看到内部字符。

例如 strawberry 可能被切成：

```text
str + aw + berry
```

或整个词一个 token。无论哪种，数出字母 r 都不是 tokenizer 直接提供的操作。

受影响任务：

- 拼写；
- 字符计数；
- 字符串反转；
- typo 鲁棒性；
- 精确格式。

一个字符改动可能改变后续全部 merge 边界，使表示跳变。

## 13. Glitch Tokens

Tokenizer 训练语料与 LM 训练语料不一致时，某些 token：

- 在 tokenizer 语料中高频而进入词表；
- 在模型训练中极少出现；
- embedding 几乎未学习；
- 触发异常、不可重复或幻觉行为。

这不仅浪费词表槽，还可能成为攻击面。

> [!important]
> Tokenizer 与模型最好在兼容数据分布上训练，并审计低频词表项。

## 14. 多语言语言模型

架构与单语模型相同，主要差异是：

1. 收集多语言数据；
2. 在混合语料上训练 tokenizer；
3. 用 MLM 或 CLM 训练同一 Transformer。

典型模型：

- mBERT；
- XLM-R；
- mT5；
- BLOOM；
- 多语 decoder LLM。

## 15. Cross-Lingual Transfer

模型在多语言预训练后，只用英语标签 fine-tune，也可能直接在其他语言 zero-shot 推理。

原因包括：

- 共享参数；
- 重叠 subword；
- 相似语义任务；
- 多语言上下文将表示对齐；
- 数字、实体和借词提供锚点。

词表 overlap 通常帮助迁移，即使部分 shared token 是 false friends，也可能提供表示连接。

但迁移并不保证所有语言同等受益。

## 16. Curse of Multilinguality

固定参数容量下加入更多语言：

- 初期低资源语言从迁移受益；
- 超过某点后，每种语言分到的容量和训练更新减少；
- 高资源语言和低资源语言都可能下降。

课件给出的 XNLI 示例中，固定模型从 7 种语言扩到 100 种时平均准确率下降。

缓解方向：

- 增加模型容量；
- mixture-of-experts；
- 语言路由；
- 更平衡采样；
- 语言专用 adapter；
- 改进 tokenizer 分配。

## 17. 训练数据混合

若按原始网页频率采样，英语等高资源语言支配训练。

可用温度采样：

$$
q_\ell
\propto
p_\ell^\alpha,
\qquad
0<\alpha<1,
$$

其中 $p_\ell$ 是语言原始比例。次幂平滑会提高低资源语言相对采样率。

代价是高资源语言训练量下降，并可能重复过采样小语料。

## 18. Tokenization Fairness

### Subword Fertility

每个词平均产生的 subword 数：

$$
F_\ell
=
\frac{\text{language }\ell\text{ 的 subword 数}}
{\text{word 数}}.
$$

fertility 高意味着：

- 同样意义占更多 context；
- attention 和生成更慢；
- 按 token 计费更贵；
- 长度上限更快用完；
- 表示被切得更碎。

课件指出等价文本的 token 长度在语言间可相差很大，fertility 与下游性能往往负相关。

### 为什么词表会不公平

BPE 按混合语料全局频率分配 merge：

- 高频语言获得大量长 token；
- 低资源语言停留在字符或字节级；
- 不同文字系统难共享；
- 英文标点和空格模式获得更多槽。

这种差异在模型训练前已经产生。

## 19. 重新考虑 Byte-Level

Byte/character 模型可：

- 覆盖未见语言；
- 避免 glitch token；
- 直接处理字符任务；
- 对拼写噪声更稳定。

主要问题是序列长。

改进方向：

- 动态删除不重要 byte；
- 局部编码后下采样；
- hierarchical transformer；
- latent tokenization；
- 学习语言特定压缩。

MrT5 一类方法学习 delete gate，让多数层只处理部分 byte，同时保留可逆输入信息。

## 20. Tokenizer 选择清单

> [!check]
> - 训练语料是否覆盖目标语言？
> - 是否需要字符级操作？
> - 词表参数预算是多少？
> - 等价文本在各语言 token 长度如何？
> - 低频和 glitch token 有多少？
> - 新领域词和代码如何表示？
> - 上下文长度与 API 价格是否公平？
> - 更换 tokenizer 后如何重新训练 embedding 与模型？

## 21. 小结

- Token 是模型的计算单位，不等同于词或语素。
- BPE 反复合并高频相邻 pair；训练产物包括有序 merge rules。
- 子词消除 OOV，却使字符操作、typo 和 glitch token 成为问题。
- 多语言迁移来自共享表示，但固定容量会产生 curse of multilinguality。
- Token fertility 同时影响质量、速度、上下文和价格，是多语言公平性的核心指标。
- Byte/character 模型以更长序列换取开放词表、字符可见性和跨语言覆盖。
