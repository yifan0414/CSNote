# CS224N 14：基准测试与评估

> [!abstract] 本节定位
> 分析基准的设计、寿命和偏差，比较自动指标、人类评测与 LLM-as-a-judge。

## 学习目标

- [ ] 将评什么与怎么评分开
- [ ] 识别泄漏、标注伪影、prompt 敏感性和 Goodhart 效应
- [ ] 为开放生成设计可复核评测

## 知识笔记

> [!info] 课件范围
> 对应 Evaluation PPT 第 4–77 页：LLM benchmark 的生命周期、SQuAD/动态/对抗基准、经典与模型式指标、信息论指标、人类评审、LLM judge、Goodhart 定律、数据污染和 prompt 敏感性。

## 1. 评测的两个问题

评测必须分开：

1. **What to evaluate on**：用什么任务、数据和能力定义；
2. **How to evaluate**：如何把输出变成分数。

一个指标算得非常精确，也不能修复 benchmark 测错能力的问题。

## 2. Benchmark 如何推动又限制进展

共享 benchmark 提供：

- 固定输入；
- 明确输出；
- 统一指标；
- 可比较 leaderboard。

但当模型快速进步时，benchmark 的寿命缩短：

- 分数饱和；
- 数据进入预训练语料；
- 社区反复调参导致 test overfitting；
- 人类不再是稳定性能上限；
- 新模型擅长题型但未必掌握目标能力。

## 3. 多任务基准

### GLUE 与 SuperGLUE

将多种语言理解任务统一格式，测试：

- entailment；
- sentiment；
- paraphrase；
- coreference；
- reading comprehension。

多任务平均分方便比较，但会掩盖任务间差异和数据规模差异。

### MMLU

覆盖 57 个学科，主要使用 multiple-choice。它从纯语言理解扩展到知识和专业考试。

局限：

- 选项提供额外线索；
- 题目可能污染；
- 单一准确率不反映置信和推理过程；
- 相似题库可被训练记忆。

### 更难的基准

课件列出 GPQA、Humanity's Last Exam、FrontierMath 等。构造更难题目可以延后饱和，但“难”不自动等于“重要”或“真实”。

## 4. 题型决定评分难度

| 输出类型 | 评分方法 | 主要问题 |
| --- | --- | --- |
| Multiple choice | Accuracy | 猜测、选项提示、格式 |
| 短答案 | Exact match / 数值等价 | 同义表达、单位、格式 |
| 单句生成 | overlap / semantic metric | 多个正确答案 |
| 长文本 | 人类或 LLM judge | 标准主观、成本、偏差 |

开放输出越长，唯一 gold answer 越不合理。

## 5. SQuAD 的意义

SQuAD 将阅读理解扩展为大规模 span 抽取，推动：

- 统一训练与评测；
- 端到端神经 reader；
- 人类与模型比较；
- leaderboard 快速迭代。

SQuAD 2.0 加入不可回答问题，要求系统不仅找 span，还判断证据是否足够。

但数据收集过程可产生 annotation artifacts：标注者写问题的方式留下表面模式，模型可能利用模式而非真正理解。

## 6. 对抗与动态 Benchmark

### 对抗收集

让人类针对当前模型寻找失败样本：

1. 模型先回答；
2. 标注者尝试使模型失败；
3. 收集成功攻击；
4. 重新训练与评测。

优点是聚焦前沿错误，缺点是：

- 数据偏向被攻击模型；
- 样本可能不自然；
- 下一代模型很快再次饱和；
- 标注者可能利用格式漏洞。

### 动态 Benchmark

持续加入新数据或隐藏时间切片，可降低记忆与长期 test overfitting。

但版本持续变化后，不同时点的分数未必可直接比较，必须记录 dataset version。

## 7. 行为式 Benchmark

与其只测学科正确率，还可针对行为构造最小对照：

- 否定；
- 数值变化；
- 社会偏见；
- 事实一致性；
- 指令优先级；
- 鲁棒性。

最小对照只改变一个因素，更容易解释模型到底对什么敏感。

## 8. 经典文本指标

### BLEU

BLEU 以 n-gram precision 为核心，并加入 brevity penalty：

$$
\operatorname{BLEU}
=
BP\cdot
\exp
\left(
\sum_{n=1}^{N}w_n\log p_n
\right).
$$

适合语料级机器翻译比较，但不理解语义。

### ROUGE

ROUGE 更强调 reference 内容是否被生成覆盖，常用于摘要。ROUGE-N 可看作 n-gram recall。

### METEOR、CIDEr、TER

- METEOR 加入词干和同义匹配；
- CIDEr 对图像描述中的共识 n-gram 加权；
- TER 估计将生成编辑成 reference 所需操作。

## 9. Surface Overlap 的局限

同义回答可能词面不同而被低分：

> They went to the Taylor Swift concert.

与：

> They attended the Eras Tour.

相反，只差一个否定词的错误回答可能有很高 overlap。

因此 n-gram 指标：

- 假阴性：语义正确但表面不同；
- 假阳性：表面相似但事实相反。

## 10. Model-Based Metrics

### BERTScore

使用上下文化 embedding 匹配生成与 reference token：

$$
s_{ij}
=
\cos(h_i^{\text{cand}},h_j^{\text{ref}}).
$$

再做软 precision/recall 匹配。

### Word Mover's Distance

把词 embedding 间距离作为运输成本，求将一段文本的词质量移动到另一段文本的最小成本。

### BLEURT/COMET

训练模型拟合人工质量判断。它们能捕获更复杂语义，却继承 evaluator model 的：

- 偏见；
- 领域失配；
- 事实敏感度不足；
- 版本和复现成本。

例如“出生于 1942”与“出生于 1924”embedding 很接近，但事实完全不同。

## 11. 信息论指标

### Shannon Entropy

$$
H(P)
=
-\sum_i p_i\log p_i.
$$

衡量离散分布平均不确定性。

### Vendi Score

用样本相似度矩阵的谱定义有效多样性，可看作把 entropy 扩展到相互相似的样本集合。

梯度表示上的 G-Vendi 试图衡量数据在“学习信号”而非词面上的多样性。

### Distinct-n 与 Self-BLEU

- Distinct-n：不同 n-gram 数与总 n-gram 数之比；
- Self-BLEU：把集合中一个样本对其他样本计算 BLEU；越高通常越不多样。

二者容易被无意义随机文本欺骗，因此多样性必须与质量联合报告。

## 12. 分布距离与 MAUVE

KL divergence：

$$
D_{\mathrm{KL}}(P\|Q)
=
\sum_xP(x)\log\frac{P(x)}{Q(x)}.
$$

直接估计人类文本与模型文本的高维分布非常困难，且支持集不重叠会造成问题。

MAUVE 大致：

1. 将文本嵌入；
2. 聚类量化为离散分布；
3. 计算多个 KL 权衡点形成 divergence frontier。

它测整体分布相似性，不等于单条回答事实正确。

## 13. Reference-Based 与 Reference-Free

### Reference-Based

与 gold answer 比较。问题：

- reference 质量有限；
- 正确答案空间覆盖不足；
- 模型对 reference 特有风格过拟合；
- 生成任务可能没有唯一答案。

### Reference-Free

直接根据：

- 输入；
- 输出；
- 事实来源；
- rubric

判断质量。例如翻译质量估计不需要 reference，事实指标可把陈述分解后检索验证。

Reference-free 不等于没有标准，它把标准放进 evaluator 或外部证据。

## 14. 人类评审

高质量人评需要：

1. 明确 rubric；
2. 校准样例；
3. 随机和盲化顺序；
4. 多评审；
5. 分歧解决；
6. 一致性统计；
7. 报告标注者背景。

人类并非绝对 oracle：

- 疲劳；
- 领域知识不足；
- 位置与长度偏好；
- 对流畅错误不敏感；
- 价值观分歧。

## 15. LLM-as-a-Judge

常见做法：

- pointwise：单独给每个回答分数；
- pairwise：在两个回答间选择；
- rubric-based：按多个维度评分；
- jury：多个 judge 聚合。

### 偏差

- position bias；
- verbosity bias；
- self-preference；
- style bias；
- prompt sensitivity；
- 对引用或事实验证不足。

### 校准

应与独立人评比较：

- 相关；
- pairwise agreement；
- 分组偏差；
- 顺序交换；
- 对抗样例；
- judge 更换后的稳定性。

## 16. Goodhart's Law

当一个指标成为优化目标，它会逐渐失去作为指标的价值。

模型或开发者会找到：

- benchmark 捷径；
- judge 偏好；
- 格式漏洞；
- 数据污染；
- 过度冗长；
- reward hacking。

因此评测应：

- 使用多指标；
- 保留隐藏测试；
- 定期更新；
- 做真实场景验证；
- 分析失败而非只追排行榜。

## 17. 数据污染与去污染

污染来源：

- 测试题出现在预训练网页；
- benchmark 解析、答案或讨论进入语料；
- synthetic data 重复测试模式；
- 用户评测请求被后续训练收集。

检测可使用：

- exact/subsequence match；
- n-gram overlap；
- embedding retrieval；
- canary；
- 时间切分；
- 训练数据审计。

去污染并不完美。公开 benchmark 的语义相似变体也可能被模型见过。

## 18. Prompt 敏感性

评测结果可能随：

- few-shot 示例；
- 顺序；
- system prompt；
- 输出格式；
- temperature；
- 答案解析器

变化。

至少应固定并公开 prompt 和 decoding config。若目标是测稳健能力，还应报告多个合理 prompt 的分布，而非只选最好结果。

## 19. 评测报告模板

> [!check]
> - 能力定义；
> - 数据来源与版本；
> - 污染分析；
> - prompt 与 decoding；
> - 指标定义；
> - evaluator 版本；
> - 置信区间；
> - 分组结果；
> - 成本与延迟；
> - 失败样例；
> - 人评或 judge 校准。

## 20. 小结

- Benchmark 决定“测什么”，metric 决定“怎样打分”。
- 更难题目能延缓饱和，但不能自动保证现实相关性。
- 词面、embedding、人类和 LLM judge 各有不同误差。
- 数据污染、prompt 敏感和 Goodhart 效应会让分数失真。
- 可信评测应多维、版本化、可复核，并公开不确定性和失败样例。
