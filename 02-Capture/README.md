# Capture 收集与整理

所有新收集的灵感、工具链接、网页摘录和视频讲义统一存入 `02-Capture/灵感与工具/`，通过 [[02-Capture/灵感与工具.base|灵感与工具]] 查看。笔记按主题命名。

## 收集入口

- 在「灵感与工具」目录新建空笔记，执行 `Templater: Open insert template modal`，选择 [[Templates/灵感收集|灵感收集模板]]，默认 `类型: idea`、`status: unread`。
- 收集工具时，改选 [[Templates/工具链接收集|工具链接收集模板]]；已套用灵感模板的条目可以直接把 `类型` 改为 `tool`。
- 视频讲义由 `bilibili-lecture-notes` 技能保存到同一目录；新生成的讲义仍为 `unread`，等待本人阅读和判断。
- 图片统一放入 `_assets/images/`，按 `<主题>-<序号>-<简述>.png` 命名，并用 `![[_assets/images/<name>.png|900]]` 引用。

本机 Templater 的“新建文件时自动触发”当前关闭，手动建笔记时需要选择模板；通过技能生成的讲义会直接写入 YAML。

## 字段约定

| 字段 | 用途 |
|---|---|
| `类型` | `idea` 表示想法、知识摘录或讲义；`tool` 表示工具、脚本或操作记录。 |
| `status` | 与论文库一致，使用 `unread`、`reading`、`read`、`archived`。 |
| `来源` | 平台或来源性质：如 `Bilibili`、`YouTube`、`web`、`thought`；无法确认时留空。 |
| `网址` | 原始来源链接；自己的想法或来源不明的旧记录可留空，不以文中的其他链接冒充原文。 |
| `发现时间` | 收集日期，使用 `YYYY-MM-DD`；没有另记发现日期时，默认与 `created` 相同。 |
| `tags` | YAML 列表，只放内容主题；没有合适标签时用 `[]`，不重复记录类型和来源。 |
| `created` | 笔记创建日期，使用 `YYYY-MM-DD`，后续修改时保留。 |
| `updated` | 最近修改日期，使用 `YYYY-MM-DD`；修改笔记时更新。 |

已有 `aliases` 等属性继续保留。历史创建日期优先迁移自已有的 `创建时间` 或 `created`；缺失时依据本地文件系统的创建日期补齐。旧日期统一到日，不改成此次整理日期。

## 处理状态

| 状态 | 含义 | 何时改变 |
|---|---|---|
| `unread` | 已收集，尚待本人阅读、判断或补充。 | 新收集时默认使用。 |
| `reading` | 手动标记为阅读中。 | 可按需要设置；下次打开时自动变为 `read`。 |
| `read` | 已打开阅读，或本人已手动标记为已读。 | 打开 `unread` 或 `reading` 笔记时自动变更，也可手动设置。 |
| `archived` | 暂时不再使用，保留备查。 | 确认不需要继续关注时使用。 |

排版整理、补全 YAML、添加链接和 AI 生成正文不会单独触发阅读标记；在 Obsidian 中打开笔记后，按下面的规则自动更新状态。

## 打开即标记为已读

本库已启用本地插件 **Capture & Papers 阅读状态**。在 Obsidian 中打开「灵感与工具」笔记，或 `Paper/` 下带有 `paper/arxiv`、`paper/pdf` 标签（含子标签）的论文 Markdown 笔记，并切换到该标签页时，会将 `status: unread` 或 `status: reading` 改为 `status: read`，同时把 `updated` 更新为当天日期。两个 Base 会随之显示绿色「Read」Badge。

- 编辑视图和阅读视图都计为打开；悬停预览、查看 Base 列表、仅点击原文网址不计入。
- 已归档、已经处理、缺少状态或使用其他状态的笔记不会被改写；其他目录不受影响。
- 启用插件时不会批量处理已有笔记，也不会扫描历史阅读记录。
- “Read”在这里表示已经打开过，不判断是否读完整篇文章。

误打开后，在命令面板搜索 `Capture`，执行 **Capture & Papers 阅读状态：将当前笔记标记为未读**。本次保持打开时不会立即再次自动标记；下次重新打开时仍按上述规则处理。

需要停用时，在 Obsidian「设置 → 第三方插件」中关闭 **Capture & Papers 阅读状态**。

更新插件文件后，需要关闭再开启该插件，或重启 Obsidian，才能让正在运行的实例加载新逻辑。旧实例可能仍显示名称 **Capture 阅读状态**。

旧 Capture 状态已迁移：`状态: inbox` → `status: unread`，`状态: processed` → `status: read`，`状态: archive` → `status: archived`。新笔记统一使用 `status`。

## Base 的使用

- **全部**：默认视图，查看所有条目，包括状态填写异常时未进入其他视图的笔记。
- **收件箱**：显示 `unread` 或缺少状态的条目，按收集日期从旧到新排列。
- **阅读中**：查看 `reading` 条目。
- **已读**：查看已经打开阅读或手动标记过的材料。
- **工具 / 灵感**：按类型浏览未归档条目。
- **归档**：查看暂时不再使用的材料。

「状态」与 `Paper/Papers.base` 共用 Badge：灰色「Unread」、蓝色「Reading」、绿色「Read」、灰色「Archived」。它是显示列；要手动改变状态，可打开笔记编辑 YAML 的 `status` 属性，也可在 Base 的「属性」菜单中显示「修改状态」列后编辑。

「内容更新」取自 `updated`；需要核对文件实际修改时间时，可在 Base 属性菜单中显示「文件更新」。模板只负责创建时填入日期，不会在每次编辑时自动刷新 `updated`。

## 整理去向

先补一句这条内容解决什么问题，再决定是否保留。能接入已有主题时，在正文「关联笔记」中填写实际存在的双链，保留原始材料以便追溯。

稳定知识可以进一步整理到 `06-LLM`、`03-Tool` 等主题目录，并与收集条目互相链接。同一主题的不同角度可以分别保留，例如注意力缩放的方差推导与温度解释。
