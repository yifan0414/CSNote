主要原因：现在这个策略在高帧数下没有真正变成“更强的全局理解”，只是把 32 帧的结构覆盖继续扩张到 64 帧。

从结果看很明显：

| frames | allglobal delta | 原始 global delta |
| --- | ---: | ---: |
| 8 | +1.70 | +3.0 |
| 16 | +1.56 | +4.0 |
| 32 | +0.85 | +3.3 |
| 64 | +0.52 | +0.8 |

也就是说，整体还正向，但边际收益明显衰减；global 本身在 64 帧掉得最多。

核心原因我认为有几个：

1. **低帧数问题是“覆盖不足”，高帧数问题变成“信息过载”**
   8/16 帧时，结构化 event skeleton 能解决“别漏掉关键事件”的问题，所以收益大。
   到 64 帧时，覆盖已经不是主要瓶颈，VLM 反而要在更多视觉 token 里判断重点。额外帧很多是低信息密度、重复、过渡、背景或干扰帧。

2. **当前 64 帧策略只是扩张，不是压缩后的全局表示**
   现在 `event_structure_multiscale_packet` 在 `k > 16` 时走 expansion stage：
   - dense -> `event_structure_scale_packet`
   - bounded_gap -> `event_facility_packet`
   - sparse/tail -> `event_structure_scale_v2_packet`

   这适合 32 帧，因为 32 帧还能像“事件骨架 + 局部补充”。
   但 64 帧继续这样选，本质是“给每个结构区更多原始帧”，不是“生成更好的全局摘要”。

3. **global 问题需要的是事件级语义，而不是更多 frame-level diversity**
   global 问题常问：
   - 主要发生了什么
   - 哪个说法正确/不正确
   - 哪个东西没有出现
   - 视频主题/灾难/事件类型是什么

   这些需要的是事件级归纳、排除、对比。64 个裸帧并不会自动形成更好的事件摘要，反而可能让模型被局部片段牵引。

4. **64 帧会削弱 VLM 的注意力集中度**
   Qwen 2.5-VL 看到更多帧后，不一定等价于“理解更多”。视觉 token 更多时，模型可能：
   - 平均注意力被稀释
   - 被局部显著但无关的帧干扰
   - 对重复帧产生过强先验
   - 在多选题里更容易被某个局部证据误导

5. **当前 global 分类本身不纯**
   原始 global 里确实有很多全局问题，但也混有需要 temporal/local 证据的问题。
   64 帧时你把所有样本都走 global，local 还能 +0.8，temporal 变成 -0.2，说明“视频结构覆盖”对一部分 temporal 是不够的，更多帧没有补上推理链。

所以结论是：
**现在的策略在 8/16/32 好，是因为它找到了“事件骨架”。但 64 帧不好，是因为它没有把额外预算转化成更高层的事件记忆，只是在骨架上堆了更多原始帧。**

下一步如果继续做 64，不应该再调阈值或简单换 delegate。更合理的方向是：
**64 帧 = 16/32 帧事件骨架 + 每个事件的少量上下文/证据帧 + 去重复/去干扰约束**，而不是纯扩张。
